# 提示词边界与冲突扫描

本检查先于可生成性评估，用来发现明确的项目违规、平台边界、指令冲突和容易误读的表达。

## 判据来源

只使用以下来源：

1. 用户明确要求和项目 brief。
2. 当前交付文件中声明的模型、平台和规范（含项目已登记的冻结段与风格版本）。
3. 已核验的官方模型能力或限制。
4. 通用的语义冲突与不可观察性判断。

不得内置竞争品牌名单、年龄禁词、暴力动词黑名单、固定负面串、人数上限、反射禁令、双对比切镜或其他旧项目规则。真人名、品牌、年龄、武器和暴力是否需要改写，取决于用户目标、权利条件和已确认平台规则。

## 扫描项

- 项目明确禁止或要求的内容是否违反。
- 同一提示词中的画幅、角色身份、位置、动作、镜头、声音、字幕和风格是否冲突。
- 是否引用不存在的资产、未定义的人物或无法继承的状态。
- 是否要求模型表现气味、味道、未配旁白的内心信息等不可见不可听内容。
- 指代、左右、时间和动作主体是否含混。
- 负面要求是否与正向目标冲突，或无依据地压制必要内容。
- 是否把未经核验的经验写成平台必然规则。
- 批量资产或分镜的冻结段（项目级风格不变量）是否逐字一致；出现多套写法时，是笔误还是已登记换档。
- 冻结段是否混入了逐镜变量（景别、机位高度、主体占比、视角），导致全批被锁成同一构图。
- 静帧类资产（参考图、设定表、海报、版式底图）是否写了冲刺、跃起、击中瞬间等结晶帧动作。
- 情绪基调是否与本条的事件、光位和题材档同向。

扫描代码块、结构化提示词字段或用户指定范围；散文说明只在它会进入实际投喂内容时纳入。

## 分级

- FAIL：违反明确项目或平台规则，存在直接冲突，或缺少关键资产导致无法执行。
- WARN：有明显歧义或高风险，但可试生成。同批冻结段出现未经登记的第二套写法、冻结段混入逐镜变量、静帧写了结晶帧动作、基调与画面事件冲突，均属此档。
- INFO：可选优化。

每条结果定位到组和镜头，附原文、判据来源和建议。没有可靠来源时写“需确认”，不得伪装成合规结论。
