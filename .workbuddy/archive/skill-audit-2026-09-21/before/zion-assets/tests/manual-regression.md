# zion-assets · 人工回归

1. 剧本人物提取应覆盖主角、配角和有实际叙事作用的匿名人物，并合并别名。
2. 视频输入优先结合 ASR 与关键帧；工具缺失时明确限制，不把元数据冒充人物证据。
3. 原文事实、合理推断、设计补全和未知必须区分。
4. 年龄可保留在人物卡；生成提示词按目标模型选择直接表达或视觉化表达，不设全局禁词。
5. 参考表采用简单背景和易读光线，但不固定灰色数值、宫格数或无头全身。
6. 视图从实际镜头倒推；只要求正脸时不自动生成完整资产套装。
7. 用户要求 JSON 时符合 schema；普通人物分析不强制附 JSON。
8. 批量处理中单文件失败应记录并继续。
9. 用户要求人物、场景和道具成套制作时由本档统一处理；其中正式分镜和视频提示词交给 zion-storyboard。
10. 用户只要求场景或道具资产时，不强制先做人物卡。
11. 用户要求完整资产包时，人物、场景、道具和其他资产使用统一登记表，但保持独立 ID 与版本。
12. 粗分镜提出新角度需求时新增资产需求或版本，不在分镜提示词中偷偷重设计现有资产。
13. 未生成或未上传的资产不得声称已经绑定或可用。
14. “给角色做参考图”但未指定图像模型时，按默认 GPT Image 2 处理并记录，直接进入风格、布局、视图和参考图的确认。
15. 纯人物提取不询问图像模型；用户追加绘图提示词时按默认 GPT Image 2 处理并记录。
16. 用户回答“按你推荐”时可代选当前项并记录，未授权时不能用默认布局跳过提问。
17. 批量项目应先给出冻结段再逐张出提示词；冻结段里出现景别、机位高度或主体占比时，应指出并移入变量段。
18. 交给正式分镜的资产项必须保留 `asset_id`、`version`、`status`、`files` 与 `target_reference`；不能压缩成只有 `@显示名`。
19. `approved` 且有真实文件的资产可用于正式导演稿；含视频生成提示词时，实际引用必须为 `uploaded` 且有 `target_reference`。
18. 资产图或海报类静帧要求“冲刺、跃起、击中瞬间”时，应改为中段状态写法，并说明静帧动作上限。
19. 同批冻结段写法不一致时先确认是笔误还是换档；换档须登记新版本，不直接覆盖已交付资产。
