# 图像引擎：可选模型与适配

核验日期：2026-09-20。当前收录 GPT Image 2 与 Midjourney 两档。未收录的引擎不得输出“已适配”或“可直接生成”的提示词。

视频模型规格由 `zion-storyboard` 的模型适配档单独管理，两者独立确认；一个项目可以视频用 A、图像用 B。

## 选择指引

**默认引擎为 GPT Image 2**：图像或资产提示词未指定引擎时直接使用，并在 `meta.image_engine` 记录该默认，不为此单独追问。**Midjourney 不在默认链路内**：只有用户主动提起时才使用其参数与提示词写法；不主动推荐、不主动输出 MJ 版本提示词。

用户主动询问有哪些可选引擎时，从这里给 2–3 项并标出推荐项，等待选择。

| 需求 | 首选 | 备选 |
|---|---|---|
| 画面内需要可读文字（含中文）、版式、海报、包装、菜单、标识 | GPT Image 2 | — |
| 人物/场景/道具身份参考图，多参考一次融合 | GPT Image 2（≤16 张） | MJ V8 Edit Model |
| 风格与氛围探索、艺术化质感、要一次性多方案 | Midjourney V8.2 | GPT Image 2 低质档 |
| 迭代编辑（局部改光、换背景、换装、扩图） | GPT Image 2 自然语言编辑 | MJ Edit Model |
| 需要透明背景 PNG | GPT Image 2 不支持，改用 gpt-image-1.5 | — |
| 需要长期锁定主体跨多次编辑不变 | GPT Image 2 Character Lock | MJ 生成后筛选 + 局部编辑 |

## 引擎一：GPT Image 2

**模型与入口**：模型 ID `gpt-image-2`。官方发布为 ChatGPT Images 2.0（2026-04-21）。入口：ChatGPT / OpenAI API `/v1/images/generations`、`/v1/images/edits` / Azure AI Foundry。闭源，不入 Bedrock 与 Vertex。

**已核验能力**

- 架构内置推理（Thinking Mode）：先理解、规划、再生成、再自检，因此复杂提示词的指令遵循与版式控制强于单通道扩散模型。
- 参考图：单次最多 **16 张**（每张 ≤100MB），可同时承担身份参考、风格锚定与构图参考。
- 文字渲染：官方称跨拉丁、中文、日文、韩文、印地、孟加拉、阿拉伯等脚本 **>95%** 准确率；第三方评测报 99%（含 CJK）。中文可用，不是历史水平。
- 输出：1K / 2K / 4K 原生（最高 4096×4096）；11 种比例覆盖 1:1 至 21:9，含 9:16；单次可出 1/2/3/4 张。
- 编辑：自然语言 inpaint / outpainting，多数任务不需要手绘遮罩；支持多轮对话式连续编辑。
- Character Lock：锁定主体后，改光、改背景、改构图不动主体外观。

**局限（写作时按此规避）**

- 不支持透明背景输出。
- 高质量档延迟 30–50 秒（P99 约 60 秒），不适合当作实时预览工具。
- Token 计费，单图成本随提示词长度、参考图数量与质量档浮动；参考区间约 $0.006（低质）至 $0.211（高质）每张，Batch API 五折。

**提示词适配**

- 要渲染的文字**用引号原样写出**，并说明位置与层级（标题 / 副标 / 角标 / 包装面）。项目品牌字直接写入引号内；本通道按 [文字通道口径](#项目级覆盖与文字通道) 直接渲染，不留合成位。
- 版式用结构描述，不用“好看”“高级”这类形容词。
- 参考图一次给全并写清分工（身份 / 风格 / 构图 / 道具），不要链式多轮堆参考。
- 分辨率阶梯化：1K 试错 → 2K 复核 → 4K 定稿。
- 元数据里记录引擎与档位（见 [资产输出契约](asset-output-schema.md) 的 `meta.image_engine`）。

## 引擎二：Midjourney

**版本现状**：V8.2 为当前默认版本（2026-07-24 起）。V8 相对 V7 大约快 4–5 倍。

**参考机制按版本分档（最容易踩的坑）**

| 机制 | 参数 | 参考张数 | 原生支持版本 | 说明 |
|---|---|---|---|---|
| Edit Model + 附加参考图 | 无参数，界面操作 | 多张 | V8.x | V8 官方推荐的身份一致性路径 |
| Omni Reference | `--oref` / `--ow` | **仅 1 张** | 仅 V7 | 主体（人/物/载具/生物）；权重 1–1000，默认 100 |
| Character Reference | `--cref` / `--cw` | 仅 1 张 | 仅 V6、Niji 6 | `--cw` 0（仅面部）–100（含发型服装） |
| Style Reference | `--sref` / `--sw` | 多张 | V6 及以后 | 只传风格，不传主体；`--sw` 0–1000 |
| 图像提示 | 图片 + `--iw` | — | V6 及以后 | V7/V8.1 权重 0–3，默认 1 |

**在 V8.1 / V8.2 上写 `--oref` 会静默把任务回退到 V7 执行**；`--cref` 在 V7 及以上已标记不支持。混用版本与参数是“参考不生效”的首要原因。

**其它已核验参数**

- `--no`：负面提示，V6 及以后可用。
- `--ar`：V7/V8 最高 14:1；V8 的 `--hd` 下限制 4:1。
- `--hd` / `--sd`：仅 V8.1 及以上，`--hd` 为原生 2K。
- `--raw`：V5.1 及以后；V7 写作 `--style raw`，V8 写作 `--raw`。
- `--q`：**V8.1 起已移除**；仅 V7 可用（1/2/4）。
- `::` 多提示符：止于 6.1，V8 不支持，改在句子内写强调。

**已知失败模式**

几何幻觉（建筑结构、连接关系）、细节漂移（雀斑、logo、首饰、手指、服装花纹）、不保证像素级复制。身份锁定靠“生成后筛选 + 局部编辑”，不靠单次生成。

**提示词适配**

- V8.x 做角色/道具一致性：用 Edit Model 附加参考图，不写 `--cref` / `--oref`。
- 确需 V7 Omni Reference：`--oref <单张图URL> --ow 100–400`（过高会压掉光照与场景）。
- 风格统一用 `--sref` 指向一张已确认的锚点图，不用一堆形容词。
- 场景提示词按 [资产提示词](asset-prompt-builder.md#场景提示词的尺度链) 先写空间结构、地标材质和人物活动，再写气氛；专名后补可见特征，不用专名替代设计。
- V8.x 用连贯自然语言表达主次，不使用已停止支持的 `::` 多提示符。参数统一放在末尾，复制来的 HTML 实体与重复质量词先清理。
- 复杂城市或建筑先确保主轴、入口、桥/平台连接和人物路径；装饰元素只选必要项，不能靠 `highly detailed`、`ultra detailed` 修复几何关系。
- 中文可见文字按 [文字通道口径](#项目级覆盖与文字通道) 处理：本通道不渲染中文，原图留空、后期合成贴字。

## 项目级覆盖与文字通道

项目已确认的参数优先于本档的通用建议。

**可见文字口径（按引擎分流，2026-09-20 拍板）**

| 通道 | 可见中文与项目指定品牌字 |
|---|---|
| GPT Image 2 | 直接在画面内渲染：用引号原样写出，并说明位置与层级 |
| Midjourney | 原图留空，后期合成贴字；不依赖画面内中文渲染 |

本口径替代旧的“所有通道一律留空 + 后期合成”。切换引擎时同步切换该资产的文字生成与合成安排，并在交付说明中写明本批资产走的是渲染还是留空。

若项目已拍板唯一图像通道，本档只提供可选替代；启用替代通道前必须由用户确认，并写入 `meta.image_engine`，不改动已交付资产。

## 新增引擎入档要求

要收录第三个引擎，先补齐并写清以下各项，缺项不得声称“已适配”：

1. 官方来源与核验日期。
2. 参考图上限、可引用类型与分工方式。
3. 文字渲染能力，尤其是中文；以及该引擎应归属“直接渲染”还是“留空 + 后期合成”。
4. 输出分辨率、比例与单次数量。
5. 编辑与局部修改能力（是否需遮罩、能否多轮）。
6. 已知失败模式与规避手法。
7. 与现有引擎不同的提示词写法差异。
