# Zion 技能使用手册

版本日期：2026-09-20  
技能结构：剧本 + 资产 + 分镜 + 校验。

## 一、四个顶层 Skill

| Skill | 制作阶段 | 核心问题 | 主要交付 |
|---|---|---|---|
| [`zion-script`](zion-script/SKILL.md) | 剧本 | 故事发生什么 | 故事结构、场次式剧本、对白、人物动机与结局 |
| [`zion-assets`](zion-assets/SKILL.md) | 资产 | 画面中有什么、长什么样、如何稳定复用 | 人物/场景/道具/其他资产卡、ID、版本、参考需求、图像提示词与登记 |
| [`zion-storyboard`](zion-storyboard/SKILL.md) | 分镜 | 故事如何被拍出来 | 粗分镜、导演分镜、调度、镜头时间线、画幅适配、视频提示词 |
| [`zion-qa`](zion-qa/SKILL.md) | 校验 | 内容是否正确、连续、可生成、可使用 | 分级问题、证据、修改建议、通过项与复验结论 |

快速判断：

- 写故事、改对白、补动机：`zion-script`。
- 做人物、场景、道具、服装变体或图像提示词：`zion-assets`。
- 拆镜、设计运镜灯光转场、制作视频提示词：`zion-storyboard`。
- 检查剧本、资产、分镜、提示词或生成结果：`zion-qa`。

## 二、推荐制作流程

四个 Skill 是职责分类，不是只能单向执行的流水线。推荐使用两轮资产流程：

```text
zion-script
  锁定故事事实、人物动机、场次、对白与结局
        ↓
zion-storyboard（粗分镜）
  判断实际需要哪些人物角度、场景方向、道具状态和动作参考
        ↓
zion-assets
  建立并锁定资产，登记真实文件、版本与可用状态
        ↓
zion-storyboard（正式分镜）
  挂载真实资产，完成镜头时间线与视频提示词
        ↓
zion-qa
  做投喂前检查与生成后验收
```

简单项目可以跳过粗分镜回路：剧本明确后直接制作资产，再进入正式分镜。只做文字剧本时，不必进入资产或分镜阶段。

## 三、调用方式

可以直接描述任务让 AI 助手自动匹配，也可以显式调用：

```text
$zion-script 根据这个创意写一个90秒竖屏悬疑短剧……
$zion-assets 为附件剧本建立人物、场景和道具资产包……
$zion-storyboard 把已确认剧本拆成导演分镜和Seedance提示词……
$zion-qa 检查这套资产与分镜，修复后重新验收……
```

复杂项目建议显式点名。一次请求可以限定局部范围，不必每次跑完整流程。

## 四、`zion-script`：剧本

### 适合做什么

- 从题材、构思或一句话故事创作短片/短剧剧本。
- 扩写大纲、改编、重写、续写或细化已有正文。
- 设计故事结构、场次、对白、人物目标、阻力和人物弧线。
- 用户点名时附节拍表、场次表或简版镜头构想。

### 建议输入

- 创意或已有原文。
- 成片时长、集数、单集时长和平台。
- 题材、基调、目标观众和结局方向。
- 主角、核心冲突、必须保留内容和允许补全程度。

### 默认交付

项目参数简述 + 场次式完整剧本。不会自动附加完整资产包、正式逐镜分镜或模型提示词。

### 示例

```text
$zion-script
把下面的一句话创意发展成3集竖屏短剧，每集90秒。
现实悬疑基调，允许补充场次，但核心关系和结局方向不能改。
请先逐项确认缺失信息。
```

## 五、`zion-assets`：资产

### 资产范围

| 模式 | 典型内容 |
|---|---|
| 人物 | 人物提取、别名合并、人物卡、关系、外貌、体态、服装、状态与音色身份 |
| 场景 | 空间拓扑、出入口、固定锚点、材质、光源、时间和天气状态 |
| 道具 | 轮廓、尺寸、结构、材质、功能、文字、归属和状态变化 |
| 其他 | 独立服装、生物、载具、武器、图形文字、特效元素、声音身份参考等 |

### 适合做什么

- 从剧本、文档、视频或粗分镜提取全部资产。
- 区分原文事实、合理推断、设计补全和未知。
- 建立稳定资产 ID、版本、状态变体及相互关系。
- 制作人物参考表、场景参考、道具细节和图像提示词。
- 登记真实文件、候选、已批准及已上传引用。
- 输出完整资产包和交给分镜的缺口清单。

### 状态不要混淆

- 只有资产描述：尚未生成。
- 只有提示词：待制作。
- 已有候选图：尚未验收。
- 已批准文件：可供下游使用。
- 已上传目标入口并记录编号：可在正式生成提示词中绑定。

### 图像模型默认

需要图像提示词而未指定引擎时，默认按 `GPT Image 2` 并记录。Midjourney 只有用户主动提出时才使用。默认采用不代表图像已经生成或验收。

### 画风分层与检索

画风由三层组成，可叠加，但同一张图内不叠加互相矛盾的美术体系：

| 层 | 管什么 | 怎么点名 |
|---|---|---|
| 题材美术 | 形制、材质、器物、色板、光源倾向、锁定项 | 说题材（如“武侠江湖”“民国”） |
| 视觉语言 | 构图、镜头、调度、光色与材质气质 | 说影人或影片名（如“杜可风”“迪金斯”）；成品默认不出现人名 |
| 成像响应 | 颗粒、宽容度、肤色、黑位、色彩密度、拷贝质感 | 说胶片或印片型号（如“Portra 400”“柯达 2383”） |

风格强度用三档控制：`S1` 轻微、`S2` 标准（默认）、`S3` 强烈。

### 示例

```text
$zion-assets
从附件剧本建立完整资产包：人物、场景、道具和服装状态。
原文没有的内容允许提出设计补全，但必须单独标注。
先输出资产登记和缺口，再为实际需要的资产制作GPT Image 2提示词。
```

只做人物：

```text
$zion-assets
只提取全部人物，合并别名和称谓，输出人物总览、关系表和JSON。
只采用原文证据，不补写外貌。
```

只做场景：

```text
$zion-assets
为“白玉天城”建立场景资产：空间中轴、门楼、台地、桥与水系连接、材质和所需参考角度。
不要添加人物资产或正式分镜。
```

## 六、`zion-storyboard`：分镜

### 适合做什么

- 将大纲或剧本制作成粗分镜或正式导演分镜。
- 优化景别、角度、构图、调度、运镜、灯光和转场。
- 设计对白场、动作场、长镜头和多人关系。
- 配平对白、动作、声音和视觉读取时间。
- 按视频模型拆分生成组并输出视频提示词。
- 做横屏、竖屏和其他画幅适配。

### 粗分镜与正式分镜

| 类型 | 可以做什么 | 资产要求 |
|---|---|---|
| 粗分镜 | 确定事件覆盖、空间、镜头需求和资产缺口 | 可以使用待制作占位，但必须标注 |
| 正式分镜 | 完成逐镜时间线、连续状态和视频提示词 | 导演稿可用有真实文件的 approved 资产；视频提示词只能绑定有目标引用的 uploaded 资产 |

`zion-storyboard` 可以提出资产需求，但不制作图像资产，也不在视频提示词中重新设计人物、场景和道具。

### 建议输入

- 已确认的大纲或剧本。
- 需要粗分镜、正式分镜、视频提示词还是局部优化。
- 原文保真程度。
- 平台、画幅、总时长和单次生成时长。
- 已有资产登记、参考文件和缺口。
- 声音、口型、字幕、旁白和配乐要求。

### 视频模型默认

需要视频提示词而未指定模型时，默认按 `Seedance 2.5` 并写入参数摘要。只做导演分镜时可以不问模型。默认采用不代表已经实际生成验证。

### 示例

```text
$zion-storyboard
把附件剧本制作成9:16正式导演分镜和Seedance提示词。
严格保留对白和结局，允许补充不改变剧情的表演与环境互动。
资产只使用附件登记表中状态为approved或uploaded的项目。
```

粗分镜需求：

```text
$zion-storyboard
先做粗分镜和资产需求清单，不输出正式视频提示词。
重点判断需要哪些人物角度、场景方向和道具状态。
```

局部优化：

```text
$zion-storyboard
只优化第6—9镜的运镜、灯光和转场，不改对白，不重做资产。
```

## 七、`zion-qa`：校验

### 四种模式

| 模式 | 检查对象 | 核心问题 |
|---|---|---|
| 结构与一致性 | 剧本、资产登记、分镜、时间码、ID和引用 | 是否自洽、引用真实、状态连续 |
| 观众盲读 | 剧本或分镜 | 人物、动机、时间、因果是否看得懂 |
| 投喂前可生成性 | 资产、分镜和生成提示词 | 指令是否清楚、冲突、超载或缺少真实引用 |
| 生成结果验收 | 已生成图片或视频 | 应保留、后期修、重剪、重生成还是重写 |

默认只报告，不修改。用户明确要求“检查、修复并复验”时才直接改动。涉及故事方向、业务规则或关键设计选择时列为待确认项。

问题等级：

- P0：阻止交付、违反明确规则或使关键内容不可用。
- P1：明显损害连续性、理解或生成成功率。
- P2：可选优化，不阻止当前交付。

### 示例

```text
$zion-qa
检查剧本、资产登记和正式分镜之间的一致性，并执行投喂前可生成性验收。
直接修复P0/P1问题后复验；涉及剧情方向的选择列为待确认。
```

## 八、职责边界

| 事项 | 负责 Skill | 其他 Skill 如何处理 |
|---|---|---|
| 人物动机、对白、结局 | `zion-script` | 资产和分镜只继承，不擅自改写 |
| 人物、场景、道具外观 | `zion-assets` | 分镜通过 ID 引用，不重新设计 |
| 镜头、调度、灯光、转场 | `zion-storyboard` | 剧本可给倾向，资产只提供支持角度 |
| 图像提示词 | `zion-assets` | 分镜不输出图像引擎版本 |
| 视频提示词 | `zion-storyboard` | 资产只提供引用与稳定锚点 |
| 独立验收 | `zion-qa` | 各制作 Skill 仍需做普通交付前检查 |

## 九、共同规则

1. 用户本轮明确要求优先于模板和历史经验。
2. 信息不足时每轮只问一个关键问题；用户授权“你定”后才代选。
3. 不把热门教程、一次案例或旧平台经验提升为全局硬规则。
4. 原文事实、推断、设计补全和导演补充必须区分。
5. 自动脚本通过只代表结构检查，不等于艺术质量或生成结果已经验证。
6. 不把待制作、候选或未上传资产冒充可用引用。
7. 图像模型与视频模型分别管理：图像归资产，视频归分镜。

### 跨 Skill 交接契约

新项目统一使用 `handoff_schema_version=1.0`：

- 剧本建立 `project_id`、`script_version` 和稳定 `scene_id`；修订时记录受影响场次。
- 资产包继承项目与剧本版本，并保留每项资产的 `asset_id`、`version`、`status`、`files`、`target_reference`。
- 分镜通过 `source_scene_id` 回指剧本，通过 `asset_refs`、`character_refs`、`scene_refs`、`prop_refs` 引用资产；禁止只保留显示名而丢失版本和状态。
- 正式导演稿可使用带真实文件的 `approved` 资产；进入视频生成提示词的资产必须为 `uploaded` 且具有 `target_reference`。
- QA 先核对项目、源版本、场次和资产引用，再检查内容与可生成性。任何源版本失配都不能以普通连续性检查通过代替。

## 十、常见路由

| 请求 | 使用 Skill |
|---|---|
| “写一个完整复仇短剧” | `zion-script` |
| “提取全部人物并做人物卡” | `zion-assets` 人物模式 |
| “建立场景和道具资产包” | `zion-assets` 场景/道具模式 |
| “用MJ生成仙界城市场景提示词” | `zion-assets`，用户已明确指定MJ |
| “把已有剧本拆成导演分镜” | `zion-storyboard` |
| “只优化第3镜灯光与运镜” | `zion-storyboard` |
| “检查分镜能否投喂” | `zion-qa` 可生成性模式 |
| “检查并修好后复验” | `zion-qa`，报告后修复并复验 |

## 十一、项目资料建议

```text
项目名/
├─ 01-brief/          项目要求、平台、时长、禁改项
├─ 02-script/         大纲、剧本和对白版本
├─ 03-assets/         资产登记、人物、场景、道具及其他资产
├─ 04-storyboard/     粗分镜、正式分镜和连续状态
├─ 05-video-prompts/  按视频模型区分的生成提示词
├─ 06-generations/    实际生成结果
└─ 07-qa/             验收报告和复验记录
```

## 十二、使用前检查

- [ ] 已选择剧本、资产、分镜或校验阶段
- [ ] 输入材料和版本明确
- [ ] 严格原文或允许补全已经说明
- [ ] 交付范围已点名
- [ ] 需要资产时已说明类别和下游用途
- [ ] 需要分镜时已说明粗分镜或正式分镜
- [ ] 图像模型与视频模型没有混为一项
- [ ] 已有资产、候选资产和待制作资产已区分
- [ ] QA任务已说明只报告还是修复并复验

## 十三、修改后校验

工作区由 codex 与 WorkBuddy 共同维护，**流程、并发规则与清理纪律的唯一来源是工作区根目录的 [`AGENTS.md`](AGENTS.md)**，两处都按它执行。三个工具：

| 工具 | 用途 |
|---|---|
| `.workbuddy/tools/skill_lint.py` | 查构建垃圾、无引用文件、内容重复、断链与失效锚点、跨技能相对路径链接；`--meta` 附加说明性文本候选 |
| `.workbuddy/tools/skill_guard.py` | 技能写租约（`acquire`／`release`／`status`）与基线快照（`snapshot`／`check`），防两个会话互相覆盖 |
| `.workbuddy/tools/sync_skills.py` | 镜像到安装目录，`--target codex|workbuddy` 只同步自己那份，`--dry` 只报差异 |

- 当前入口：[`zion-script`](zion-script/SKILL.md)、[`zion-assets`](zion-assets/SKILL.md)、[`zion-storyboard`](zion-storyboard/SKILL.md)、[`zion-qa`](zion-qa/SKILL.md)。
- 旧入口 `zion-character` 已并入 `zion-assets`；旧入口 `zion-studio` 已拆为 `zion-assets` 和 `zion-storyboard`。
- 拆分时废弃的旧参考文件：`omni-reference-assets`、`emotion-module-library`、`16-production-pipeline`、`creative-confirmation`、`novel-adaptation`。其职责已并入现有档：全能参考资产模式 → `zion-assets` 的 [资产输出契约](zion-assets/references/asset-output-schema.md)；创意确认 → 各 Skill 的“逐项需求澄清”；小说改编 → `zion-script` 的“已有正文”改编；生产流水线 → 本手册“推荐制作流程”。
- 四个技能均支持单独安装：跨技能引用只写技能名和档名，不写相对路径，因此单独取用任一技能都不会出现断链。
- `parse_input.py` 在 `zion-assets` 与 `zion-storyboard` 各存一份，供各自单独安装；两份内容必须完全一致，由 `skill_lint.py` 的 DECLARED DUPLICATE 项校验。
- 工作区与技能安装目录已同步（如 `~/.codex/skills` 或 `~/.workbuddy/skills`）；维护时先在工作区修改、校验，再同步到安装目录。
- 安装后若新 Skill 未出现在选择器中，重启对应客户端（Codex / WorkBuddy）再检查。
