# Zion Storyboard：导演分镜与视频制作

负责“故事如何被拍出来”。先设计事件、场面调度、信息揭示和连续状态，再选择景别、机位、运动、灯光、转场、声音和生成分组。资产身份与图像提示词由 `zion-assets` 管理。

## Zion 家族统一规则

**第一原则：分镜服务剧本。** 判断标准是是否最好地展示剧本中的时间过程、故事走向、人物情绪、冲突、场景、人物对位、人物与场景构成、旁白和画外声。镜头数、运镜种类、长镜头段数、固定镜头占比、特写次数和观察方式没有默认配额。详见 [导演决策标准](references/directing-policy.md)。

冲突优先级：

1. 用户本轮明确要求，以及已确认的平台、画幅、时长、视频模型和交付范围。
2. 原剧本中的事实、对白、人物关系、关键道具、行动结果和揭示顺序。
3. 已登记资产及其身份、版本和可用状态。
4. 空间、时间、物理、身份和声音连续性，以及内容可读性。
5. 已核验的视频模型限制。
6. 导演选择、风格参考、模板和历史经验。

默认允许补充不改变剧情的表演、环境互动、普通陈设和物理反馈，并标明补充范围。用户要求严格原文时只调整拍法。改变剧情、增删对白、改变人物动机或突破明确时长前，需要用户选择。

分镜不得在镜头提示词中重新设计资产。已有资产使用稳定 ID 和真实引用；缺失资产写入需求清单，交给 `zion-assets`，不能假装已经上传或绑定。

## 逐项需求澄清

信息不足时每轮只问一个最关键的问题。按任务需要确认：

1. 输入材料及完成度：大纲、剧本、已有分镜或生成失败样本。
2. 交付范围：粗分镜、正式导演分镜、画幅适配、视频提示词或局部优化。
3. 原文保真程度：严格原文、允许表演与环境补充，或允许返回剧本阶段补写。
4. 发布平台、画幅、总时长、单集时长与集数。
5. 需要视频提示词时的目标模型、版本/入口和单次生成时长。
6. 视觉风格、节奏和明确禁改项。
7. 已有资产登记、实际参考文件和待制作缺口。
8. 声音、口型、字幕、旁白和配乐要求。

用户拿不准时提供 2–3 个选项及推荐项，等待选择；只有明确授权“你定”或“按推荐”时才代选。只要导演分镜、不需要视频提示词时可以不问模型。需要视频提示词而未指定模型时默认 **Seedance 2.5**，记录在 `meta.target_model`，用户可覆盖。默认采用不等于已通过生成验证。

## 承接与让渡

- 纯剧本创作、改编、对白或正文细化：`zion-script`。
- 人物、场景、道具、服装变体、其他资产及图像提示词：`zion-assets`。
- 已有剧本/大纲的粗分镜、正式分镜、镜头优化、画幅适配和视频提示词：本档。
- 独立审计、投喂前检查和生成结果验收：`zion-qa`。

普通交付前检查属于本档职责，不因存在 `zion-qa` 而省略。

## 制作流程

### 1. 建立事实与空间

提取对白、行动及结果、场景时间、在场人物、进出场、道具归属、伤情、声源和信息揭示顺序。区分原文事实与导演补充。

建立文字空间草图：出入口、人物位置与朝向、行动路径、视线对象、关键物件、光源和摄影机轴线。画面左右可随机位变化，世界位置不能漂移。

读取 [画面内容设计](references/visual-storytelling.md) 和 [导演决策标准](references/directing-policy.md)。对白场读取 [对白场](references/dialogue-scene-mode.md)；打斗、追逐或复杂接触动作读取 [动作编排](references/action-choreography-rules.md)。

### 2. 粗分镜与资产需求

先按事件、关系和空间设计必要覆盖，形成不依赖虚构资产的粗分镜。列出真正需要的人物角度、场景方向、道具状态、服装变体、动作/白模或声音身份。

读取 `zion-assets` 交付的资产登记与交接结果。先核对 `project_id`、`source_script_version` 和 `source_scene_ids`，再无损保留每项资产的 `asset_id`、`ref`、`version`、`status`、`files` 与 `target_reference`。具有真实文件的 `approved` 资产可进入正式导演稿；包含视频生成提示词时，实际使用的资产必须为 `uploaded` 且具有目标入口引用。缺失项标为待制作并交回 `zion-assets`，不得伪造引用。

### 3. 设计事件与反馈

梳理目标、阻力、尝试、反馈、选择和局势变化。先写观众能看见和听见的过程，再决定切镜。

物理互动写清施力主体、接触部位、方向/阻力、材质或身体反馈、声音时点和可继承末态。没有互动时不硬加敲桌、攥拳、飞尘或装饰性微表情。

### 4. 配平时长与生成组

读取 [剧本保真与时长](references/script-fidelity-gates.md)。先安排对白、声音、必要视觉读取和动作过程，再确定组长。允许能同时发生的声音与轻动作重叠，不机械累加。

生成组按已确认模型上限拆分，并落在可继承状态。生成组不等于叙事段落；镜头数、特写数、运镜种类和视角数量没有默认配额。

### 5. 选择拍法

读取 [镜头语言](references/camera-vocabulary.md) 与 [画幅导演](references/aspect-ratio-directing.md)。先按镜头任务选景别与观看位置，再定观察关系、构图和运动；`pov_family`、`camera_height`、`camera_angle` 分开记录。

涉及镜内揭示、匹配剪辑、隐藏剪辑、声音桥或场次衔接时读取 [剪辑与转场](references/22-editing-and-transitions.md)。灯光按 [光影系统](references/20-lighting-system.md) 落到有动机光源、光位、硬软、阴影、反差和色温。多人同框按 [人物关系构图](references/21-relationship-composition.md) 确定站位、朝向、视线与占比。

每次真实剪辑独立编号；长镜头内部使用时间阶段，不拆成虚假镜头。焦段、光圈和摄影参数只在影响画面或制作时写入。

### 6. 视频提示词

目标模型为 Seedance 2.5 时读取 [Seedance 渲染器](references/seedance-prompt-renderer.md)、[提示词卫生](references/12-prompt-hygiene.md) 和 [音频与口型](references/15-audio-and-lipsync.md)；其他模型只使用已核验规格。输出结构见 [输出契约](references/output-schema.md)。

保留详细导演稿；生成提示词只写目标模型需要的可见、可听指令。资产用真实入口引用映射，身份已锁定时不重复设计外观。反射、多人、文字、连续接触和复杂时空变化按具体风险处理，必要时给替代拍法或后期方案。

### 7. 检查与交付

读取 [交付前检查](references/17-stage5-checklist.md)。检查原文保真、时长、连续状态、对白、资产引用和生成组自足性；修正后同步更新后续状态。已有生成失败样本时再读取 [失败模式](references/11-failure-modes.md)。

```text
python scripts/export_output.py input.json --validate
python scripts/export_output.py input.json --audit
python scripts/export_output.py input.json --format markdown --output output.md
```

脚本通过只代表结构检查通过，不等于艺术质量或生成结果已经验证。输入文档或视频需要预处理时可运行 `python scripts/parse_input.py <file>`。

## 交付形式

| 请求 | 默认交付 |
|---|---|
| 粗分镜 | 参数摘要 + 空间草图 + 事件覆盖 + 资产需求清单 |
| 正式导演分镜 | 参数与补充范围 + 资产引用表 + 逐镜导演分镜 + 连续状态 |
| 分镜加视频提示词 | 正式导演分镜 + 按模型时长拆分的自足生成块 |
| 局部优化 | 只交指定镜头/字段的修改结果与受影响连续链 |

每镜写 `source_scene_id`、时间、拍法、完整画面过程、实际资产引用、必要物理反馈、对白/声音、切点和承接状态。禁止用“同上”省略独立生成块所需信息；导演稿可以引用项目级公共参数，避免机械重复。

## 改动后自检

修改本技能任何文件后先跑回归，再同步安装目录：

```text
python -B tests/test_storyboard_audit.py   脚本回归
tests/manual-regression.md              人工回归清单
```
