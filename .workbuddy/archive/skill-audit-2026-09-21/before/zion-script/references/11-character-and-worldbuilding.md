# 11 · 人物设计与世界构建法

字段清单见 [04-character-setup.md](04-character-setup.md)；本档规定这些字段“怎么填才有戏”。

---

## 一、六步法（每步锁定一个不再回头改的产出）

```
1. PREMISE      一句可争辩的话，此时还没有任何角色
2. WORLD        六个维度，在任何人被选定之前填满
3. CHARACTER    9 问 + 关系网
4. STORY SPINE  10–20 个节拍，"因此 / 但是"，绝不"然后"
5. STYLE SHEET  调色板 + 灯光 + 材质 + 一份 FORBIDDEN 清单（视觉 DNA）
6. HAND OFF
```

> **World first, always.** 世界是一套**约束系统**——先定世界不让角色做什么，你就定下了他们必须成为谁。

---

## 二、九问人物表

表头：name / age / world / archetype。**只有这个角色能给出答案，模糊即是敌人。**

| # | 问题 | 说明 |
|---|---|---|
| 1 | **Thematic role** | 他们证明或证伪了前提的什么 |
| 2 | **External goal** | 具体的、当前不可能的想要 |
| 3 | **Internal goal** | 达成意味着自己是什么 |
| 4 | **Psychological need** | 伤害**自己**的缺陷 |
| 5 | **Moral need** | 伤害**他人**的缺陷 |
| 6 | **Wound** | 教会他"世界会伤人"的具体往事 |
| 7 | **Spark** | 教会他"该成为什么"的具体往事 |
| 8 | **Silhouette** | **隔着房间**看轮廓说什么 |
| 9 | **Contradiction** | 两件不匹配的事 |

**第 8 问示例**：`总是半蹲在门口，重心压在后脚，随时准备逃走或者谈条件`

## 三、Character Web（四辐诊断）

四根辐条：**Opponent / Ally / Mentor / Foil**

> **诊断法**：若拿掉一根辐条、主角在每场戏还能说同样的话，这个网就太薄了。

## 四、Style Sheet（Visual DNA）

### 4.1 六项常量

| 项 | 规则 |
|---|---|
| **Palette** | **5–7 个 hex 码**（如 `#1B3A4B`）。**注入 hex，不要用散文描述颜色** |
| **Lighting** | 光质与主光逻辑 |
| **Materials** | 这个世界由什么制成 |
| **Juxtaposition** | 一个熟悉 + 陌生的配对 |
| **Age & proportion** | 年代感与比例体系 |
| **Real-life refs** | 2–3 个演员 / 画作 / 影片，**只作观感参考，非身份复制** |

### 4.2 Forbidden List ★最有价值的字段

> 命名这个世界**"不是"什么，常常比调色板更有用**——这是最强的反俗套杠杆。

示例：
```
禁止：俗套的"淹没之城"青橙调。禁止霓虹。禁止一尘不染的表面——一切都带盐蚀。
禁止晴朗蓝天。禁止写实明星脸。禁止纯黑阴影；改用深靛蓝。
```

## 五、反套路三练

| 练法 | 做法 |
|---|---|
| **Always Ask Why** | 追问到答案让你自己意外。**任何角色都能说的一行就是刻板印象** |
| **One Wound, Two Characters** | 同一创伤造出相反的两个人，选**不那么明显**的那个 |
| **Silhouette test** | 挡住脸只凭形状能否认出？认不出就是通用设计 |

## 六、表演试读法

本节只帮助剧本确定角色的表演方向，不生成图像或视频投喂提示词。

1. 通读角色目标、阻力和关系位置。
2. 提出少量差异明确的表演方向，并说明各自要验证什么。
3. 为每个方向选择能被真实表演的试读台词，避免设定背诵或预告片旁白。
4. 记录说话方式、倾听反应、身体策略和情绪转折，供剧本修改或下游试拍。
5. 用户选定后，将结论写入人物表演备注；视觉身份交给 `zion-assets`，镜头与视频试拍交给 `zion-storyboard`。

更换角色方向时重新检查目标、阻力和策略，不能只替换几个风格形容词。

---

## 七、视觉身份边界

剧本可以记录影响故事的年龄、体态、生活痕迹、服装功能和可辨动作习惯，但不规定图像模型的禁词、皮肤词、焦段或摄影风格。完整外观、稳定锚点和模型适配由 `zion-assets` 处理；人物进入分镜后使用资产 ID 与版本，不要求跨文件逐字复制整段描述。

---

## 八、落地纪律

- 只回答当前创作真正需要的人物问题，不强制填满固定问卷。
- 场景与色彩只锁定会影响剧情的信息；完整美术与资产规则交给 `zion-assets`。
- 人物关系用于检查目标、冲突、信息差和变化，不为凑模板增加关系维度。
- 下游以 `project_id`、`script_version`、`scene_id` 和资产版本追踪一致性，而不是依赖相似措辞。

---

## 九、自检清单

- [ ] 主要人物的目标、阻力、策略和关系位置足以支撑当前故事
- [ ] 关键人物说话与行动具有可区分性，不是换名仍成立的通用设定
- [ ] 人物关系会影响选择、信息或台词，而不是独立于剧情的标签
- [ ] 年龄、体态、服装等信息只写剧情所需部分，没有越权替代资产设计
- [ ] `project_id`、`script_version` 与稳定 `scene_id` 已记录，修订影响范围可追踪
