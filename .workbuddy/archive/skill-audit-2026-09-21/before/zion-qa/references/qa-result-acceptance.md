# 生成结果验收（模式 ④）

> 定位：**视频已经生成出来之后的判定与返工决策**。与模式③（投喂前）一前一后，不可互相替代。
> 模式①查文件对不对，模式②查观众能不能看懂，模式③查提示词能不能生成，**模式④查生成结果能不能用**。

---

## 一、Take Triage：每条结果五选一判

| 判定 | 何时 | 下一步 |
|---|---|---|
| **Keep** | 该镜头的目的已达，无致命问题 | 锁定、记录、走人。次要瑕疵交给后期 |
| **Fix in post** | 瑕疵属剪辑域：调色、字幕、混音、修剪、头尾几帧不稳 | **绝不为剪辑几分钟能修的东西烧生成次数** |
| **Edit, don't regenerate** | 构图与节奏对，只有一层错了且编辑面支持 | 只修那一层 |
| **Re-roll** | 提示词是对的，样本不走运 | 同一提示词原样再来（无 seed 参数，每 roll 都是新样本） |
| **Rewrite** | **同一瑕疵出现两次** | 系统性而非运气——按规则重写提示词 |

**双向触发**：
- 同瑕疵两次 → **停止重摇**，去重写
- 每次 roll 都是**不同瑕疵** → 属随机型，走 **batch-and-cull 批量淘汰**而非重写

---

## 二、视觉接地诊断（reject_reason 受控词表）

> **纪律：无干净归属就走 `other`，绝不硬套近似值。** `other` 堆积就是未来扩展枚举的证据。

| 视觉所见 | reject_reason |
|---|---|
| 面部 / 身份相对参考变了 | `identity-drift` |
| 服装或颜色偏移 | `wardrobe-contamination` |
| 多余剪辑 / 非预期断场 | `extra-cuts` |
| 调度 / 走位崩坏 | `blocking-broken` |
| 表演平淡或错误 | `performance` |
| 机位运动错误 | `camera-wrong` |
| 物理 / 解剖违规（含手部扭曲） | `physics` |
| 屏显文字乱码 | `text-render` |
| 内容过滤拦截 | `filter-flagged` |
| 构图问题 | `composition` |
| 帧率漂移 / 时域去重 / **无合适归属** | `other` + 证据注记 |

**`--reason` 必须映射到本表**，不造新值（`"face drifted"` → `identity-drift`）。

---

## 三、判定顺序（硬门在前，审美在后）

1. **先硬门过滤不变量**——identity、wardrobe、cut 数、文字可读性、具名物理锚点。**任一不过直接出局，再好看也没用。**
2. 幸存者中只对**原本在摇的那个随机轴**（表演 / 机位 / 构图）打分。
3. **只留一条 keeper**，其余照实记 `rejected` + 真实 `reject_reason`（**分母必须诚实**）。
4. **整批都过不了硬门 → 其实是系统型问题，停止收割去改提示词。**

---

## 四、草稿能验证什么、不能验证什么

| 跨 roll 持久（草稿**能**验证） | 每次重掷（草稿**不能**验证） |
|---|---|
| 镜头数与结构服从 | 表演（表情、手势微差、微时序） |
| 调度服从（位置 / 方向 / 进出） | 命名运动内的摄影机微轨迹 |
| `@handle` 与身份污染 | clip 内节拍时序 |
| 台词位置 | 细节（烟丝、铭文可读性、反射） |
| 过滤通过与否 | |

> **细部判定必须在最终分辨率重测**——480p 恰好藏掉的就是你要判定的那些细节。

---

## 五、帧级检视（强制）

> AI 片段每帧状态独立，24 帧的 clip 是 24 次独立生成串起来的。**一帧坏就整条废。**

- 工时预算：**10 秒 clip ≈ 30–60 秒**精查/遍
- 排查重点：FPS 漂移与帧复制、边界帧突变、手部、反射、文字
- v1 仅限静帧/单帧判定；全片时域失败需逐帧审查

### 失败片 salvage

被拒的生成很少 10 秒全废——常有 **1–3 秒可用**（漂移前的干净开场、动作崩溃前的干净中段）。
**先打 in/out 点把这段切出来存库**，再决定是否重生成。

## 六、六遍诊断序列（不知道哪里错时）

| Pass | 变量 | 提问 |
|---|---|---|
| 1 | Subject | 主体描述是否无歧义？ |
| 2 | Action | 动作是否具体（物理化）且单一？ |
| 3 | Camera | 机位是否被点名，而非暗示？ |
| 4 | Style | 视觉是否被锚定（调色/镜头/布光），而非只有形容词？ |
| 5 | Audio | 音频是否作为并行轨并给了具体声音？ |
| 6 | Output | 画幅 / 时长 / 分辨率是否被有意设定？ |

**顺序非随意**：Subject 与 Action 承载最重 token 权重，多数失败落在 Pass 1–2。
**到 Pass 4 仍无变化 = 需要结构性重写，不是迭代。** 不要盲目跑满六遍（六遍 = 六次扣费）。

## 七、续接 / 延展故障图谱（12 行）

| 症状 | 成因 | 单一修复变量 |
|---|---|---|
| 续接从"计划中的结尾"而非"实际结尾"开始 | 从分镜表写提示词，没看父镜头真实末态 | 按父镜头**实际**画面重写开场 |
| 动作从头重来 | 已完成 beat 未标注已完成 | 写为已完成（"门已经开着了"） |
| 后面的 beat 提前出现 | 未来 beat 泄进本镜 | 剥离所有未来 beat，一镜一 beat |
| 身份在延展中漂移 | 链尾取代了规范身份参考 | **从原始角色参考重锚，绝不用漂移链尾的帧** |
| 接缝处方向翻转 | 轴线未锁定 | 明写方向（"从画面左走到画面右"） |
| 运动中途骤停 | 开放运动矢量未跨静帧交接传递 | 用散文携带主体/机位速度与方向 |
| 机位运动从头重启 | 缺父镜头机位相位 | 从观测到的相位开场（"推轨进行中，继续向内"） |
| 道具与前一镜矛盾 | 未跟踪道具归属/位置/状态 | 加 prop-state 行；重复道具建 prop sheet |
| 对白重复已交付台词 | 未携带音频相位 | 标记该句已交付，从音频相位继续 |
| **每次延展都比上次差** | 链深漂移（预期行为） | 重锚或有意切断；**链深上限 2，硬天花板 3** |
| 参考混进错误角色 | 缺 transfer/ignore 子句 | 拆分角色：逐图角色行 + 显式排除 |
| 事太多、没有重点 | 多个 beat 塞进一个提示词 | 未来 beat 改派给后续镜头 |

## 八、生成前检查清单（复用，放这里便于出问题时回溯）

- [ ] Subject 描述清晰
- [ ] Action 描述具体且物理化
- [ ] Camera 用了确切预设名
- [ ] 指定了视觉风格
- [ ] 提到调色或布光
- [ ] 含画幅
- [ ] 已选模型（未指定时按默认：视频 Seedance 2.5、图像 GPT Image 2，并注明）
- [ ] 提示词长度未超限
- [ ] 无互相矛盾的指令
- [ ] 需一致性时已挂参考
- [ ] Identity Block / Motion Block 已分离

## 九、记录纪律（5 秒规则）

- 每次生成都记一行到 ledger（**保留与拒绝都要记**，分母才有意义）
- 最多问一句 "keep or reject — what failed?"，不答就放弃，**绝不追问两次**
- `--reason` 必须映射到受控词表
- 480p 探索轮加 `--draft` 从头条比率中排除
- 判错了用 `amend-gen` **追加取代行**，而非改写历史

**ledger 字段建议**：`时间 | 项目 | 集/组/镜 | 模型 | 提示词版本 | 判定 | reject_reason | 备注`

---

## 十、报告格式

```
一、验收范围（文件清单 + 生成批次 + 模型 + 总条数）
二、判定分布（Keep / Fix in post / Edit / Re-roll / Rewrite 各多少，keeper 率）
三、问题清单（按 reject_reason 分组，每项含：定位 + 证据 + 建议动作 + 等级）
四、系统型 vs 随机型判定（附 ledger 证据）
五、修改汇总表（编号 / 问题 / 等级 / 定位 / 动作 / 状态）
六、复验结果（修复前后对比表）
七、复跑方式
```

> **keeper 率与预算比对照**：简单镜 2–3:1、复杂镜 4–6:1。实测显著劣化 → 是系统型问题，不是运气。
> **样本 <5 条时不要下结论**——分布是噪声，靠肉眼判。
