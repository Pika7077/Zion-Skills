# 学习资料归类与吸收

用户投喂外部学习材料（影人风格、制作经验、方法论清单）时，**怎么判归属、怎么判该不该吸收、归到哪一档**。

本档只管"**内容往哪放**"。流程本体（领租约、校验、同步、收工、提交）在根目录 `AGENTS.md`；内容归属的最终地图是 `style-single-source.md`；版本沿革在 `CHANGELOG.md`。

## 一、先判形态，再读知识点

拿材料**自己的结构词**（它用的形态名、它的组织方式）去全库 grep，而不是逐条比知识点。

**逐条比知识点会得出"全都有"。** 真缺口通常在材料独有的**形态**上，或在它独有的**组织方式**上。

实证（五次）：

| 材料 | 逐条比的结果 | 真缺口在哪 |
|---|---|---|
| 电影感三级详细程度 | 知识点几乎全有 | "提示词详略判据""画面内文字三需求"两处空位 |
| 四宫格 | 同上 | "多格拼图（一图多景）" |
| 全链条 19 条 | 11 条已覆盖 | 它**按制作环节组织**，照出"判定时机"这个维度 |
| 迪金斯六条 | 四项已覆盖且库内更严 | "介质的空间分布""材质各有中性落点" |
| 芬奇六项 | 四项已覆盖 | "多光源的分工""反常细节载体" |

后两轮的缺口同型：**都关于"这个元素承担什么任务"**——一束光、一层介质、一个细节各自的职责。"**拿掉它，读法会不会变**"这类**任务可答性**是最高产的缺口线索。

## 二、四类内容，各有落点

| 材料内容 | 落到哪 | 判据 |
|---|---|---|
| **影人／作品的视觉语言** | `zion-assets` 的导演视觉语言档（条目区） | 材料以某导演／摄影／影片为主体。姓名只作检索入口，成品写机制 |
| **与影人无关的通用判据**（光、色、镜头、剪辑、声音、构图…） | `zion-storyboard` / `zion-script` / `zion-qa` 的对应专业档 | 把影人的名字去掉，判据仍成立 |
| **题材美术倾向**（形制、材质、器物、色板） | `zion-assets` 的题材风格预设档 | 材料讲的是"某个题材该长什么样" |
| **契约／输出格式／检查表／工具** | 对应技能的同名档 | 不承担内容归属，**不进单一来源地图** |

两条纪律：

- **一条材料常常一分为二**：影人材料里，影人独有的取向归条目，可迁移的通用判据归专业档。
- **不重复**：条目里引用专业档即可，不复制内容。写法沿用 D05 的样板——"暗部保留到哪一层由 `zion-storyboard` 的光影系统档写明，不在本档重复"。

## 三、逐条判进四个格子

| 判定 | 含义 | 处理 |
|---|---|---|
| **已覆盖** | 库内已有等价或更严的判据 | **不改文件**，只在 CHANGELOG 记明"已覆盖于某档某节" |
| **真增量** | 库内确无 | 补入，并写明它比既有更进哪一步 |
| **张力点** | 与库内某条取向不同，但两者都成立 | 既不当缺口也不当错误——写成"按项目取向择一"，或注明两条相反取向不混用 |
| **不吸收** | 见 §四 | 记入 CHANGELOG 的"未吸收"栏 |

"已覆盖"也要落笔：写清对应哪一档哪一节。同样的材料再来时可直接比对，不必重查。

## 四、不吸收的三类（2026-09-21 拍板）

1. **数量配额**——"每 15 秒 5~8 次切换""单集空镜 ≤3 处""**只用一个**细节"。改写成"必须能说出它的任务／作用"，用**可答性**替代计数。
2. **硬禁令与一票否决**——"严禁／必须／一律"。改写成判据式倾向，并写明例外与边界。
3. **未核验的官方语法主张**——只写"外部资料转述，本工作区未独立核验"。

**区间数值按配额处理**（2026-09-22 补充）：焦段 28–40mm／40–65mm 未吸收，因为库内口径是"先定拍摄距离，再定焦段"，区间表会与它冲突。

## 五、防回退：材料可能带着本库已废止的旧口径

来源常常早于本库的修正，而"改后的说法"在现档正文里只以**改后的样子**存在，旧说法已经看不见了。所以不能只对照现档正文，要三步：

1. grep 材料的**结构词**（全库）
2. 对照 **CHANGELOG 的历史条目**，尤其"未吸收／已修正／同步修正"的记载
3. 与 `style-single-source.md` 核归属

实证：声音三层材料主张"对白混音音量最大"，正是 `v4.2.0` 已改掉的旧口径（现为动态听觉前景／后景）。

## 六、落地三件事，缺一即半成品

1. **接线**——判据所在档要被 SKILL.md 直链（覆盖率脚本应报 100%）；新增档必须补链。
2. **登记单一来源地图**——新增判据写进 `style-single-source.md` 对应归属行的括号里。内容档必须登记；契约／输出格式／检查表／工具档不登记。
3. **补回归**——各技能 `tests/manual-regression.md` 加 1–3 条，编号连续，句式是"**用户怎么说 → 应该怎么纠正**"。

## 七、取向差异不改写库内已有的合法选项

材料与库内取向冲突时，**不为了统一而删掉库内已登记的合法选项**。实证：

- 材料批"青橙大片"，而青橙是摄影机与质感档的合法预设 → 回归写成"按项目取向择一"，不写禁令。
- 材料说"摄影机不替人物表达情绪"，而画面内容设计档有"视角随心态走一条线" → 在条目里注明"两条择一，不混用"，不判其中一条错。

## 八、影人条目的命名与归属

条目名里的"导演／摄影"组合，代表**一组长期合作者的共同视觉语言**，不是两个人的独立标签。完整规则写在导演视觉语言档的"落地方式"节，要点：

- 用户点名**摄影指导**、作品来自他与另一导演的合作时，按该指导在这部作品里的**可迁移机制**（构图／调度／光色／材质四模块）取用，不套用条目里属于原导演搭档的部分。
- 确有需要时在条目内补一段"另一形制"。
- **不拆分已收录的组合条目**——拆分会牵动跨档引用，而长期搭档的视觉语言本就是共同产物。

## 九、吸收类改动的附加检查

在 `AGENTS.md` 标准循环之外，吸收材料还要查这几项：

```
- 追加回归前先读文件「末尾」确认最大编号   ← 撞号就出在这里
- 回归编号连续、无重复、句式一致
- CHANGELOG 的「当前规模」表已按实测更新   ← 最易漏
- 地图（style-single-source）已登记新增判据
- 接线：新档已进 SKILL.md 直链
```

两条实证：

- **编号撞车**（`v4.35.0`）：`zion-storyboard` 回归出现两个 321——另一会话在文件末尾新增了条目，而我只读到局部窗口（到 320 为止）就就地追加，双方撞号。**读局部窗口 ≠ 知道文件末尾的编号**；追加前必须取全文件最大编号再 +1。
- **规模表停摆**：`v4.33.0`、`v4.34.0` 两轮都漏更新，到 `v4.35.0` 才补上。
