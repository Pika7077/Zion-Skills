# 11 · 人物设计与世界构建法

人物设定深度跟随故事与交付需求。区分原文事实、合理推断和创作补全；外貌与行为遵循已确认的题材、时代、职业和生活经历，不默认写实、精致或明星化。

优先建立会影响行动的目标、阻力、选择与代价；身份和当前处境；人物关系与权力变化；对白节奏与压力反应；需要跨场保持的视觉和身体状态。完整人物资产交给 `zion-assets`。

## 一、从任意有效入口展开

从零设计时，可用以下顺序组织思考；已有角色、世界或正文时，从已有材料进入并迭代，不要求先填满世界设定：

1. **Premise**：故事想探索的命题或处境。
2. **World**：真正影响角色选择的规则与限制。
3. **Character**：目标、关系和行为策略。
4. **Story spine**：关键事件怎样因果相连，何处转折或停顿。
5. **Style Sheet**：影响故事识别的视觉约定，见第四节。
6. **Hand off**：锁定当前版本，说明下游需保留的内容。

发现人物或情节与世界规则冲突时，回到相关项修订；不把每步当作不可回头的永久锁定。已获批准且受保护的事实仍须遵守。

## 二、九问人物诊断

这些问题用于发现缺口，只回答当前角色需要的部分。功能角色无需补创伤史，每个角色也不必都有内在缺陷或成长弧线。

| 问题 | 可检查内容 |
|---|---|
| Thematic role | 角色怎样参与本片的命题 |
| External goal | 此刻想获得什么、阻力是什么 |
| Internal goal | 目标对其自我认识有什么意义 |
| Psychological need | 是否有伤害自己的行为模式 |
| Moral need | 是否有影响他人的行为模式 |
| Wound | 若往事影响当前选择，具体是什么 |
| Spark | 若某段经历改变了方向，怎样体现 |
| Silhouette | 远处能看到的体态与动作特征 |
| Contradiction | 是否存在有戏剧作用的冲突倾向 |

轮廓示例：总是半蹲在门口，重心压在后脚，便于随时离开或谈条件。它只适用于有对应处境的角色，不是通用性格配方。

## 三、人物关系网

对手、盟友、导师、映照角色是候选关系，不是必须齐备的四个席位。检查每段关系怎样影响目标、信息、选择或台词；删去后毫无影响的关系标签可省略。独角戏或少人物故事不为填网新增人物。

## 四、Style Sheet（Visual DNA）

### 4.1 按需选择的六个维度

| 维度 | 记录内容 |
|---|---|
| Palette | 叙事所需的颜色关系；精确交接时附色值，不规定颜色数量，自然语言也可使用 |
| Lighting | 影响剧情的光质与主光逻辑 |
| Materials | 与世界规则、生活痕迹或事件有关的材质 |
| Juxtaposition | 有表达作用的熟悉与陌生组合，可省略 |
| Age & proportion | 已确认的年代感、比例体系 |
| Real-life refs | 有需要时提供观感参考并解释用途，不自动转成身份复制要求 |

只锁定本项目需要复用的内容，其余可随创作迭代。完整资产美术由 `zion-assets` 建立，具体布光与调色执行由 `zion-storyboard` 处理。

### 4.2 Forbidden List

记录用户或项目明确排除的方向，以及经授权设计后采用的排除项；每项说明目的，避免与必须保留的内容冲突。没有排除项时可省略，不自动引入黑名单。

例：某盐蚀港口项目要求避免崭新无痕的表面，暗部保留深靛蓝而非压成纯黑。此例不构成其它项目的通用禁令。

## 五、反套路练习

- 追问角色为何这样选择，找出与其处境有关的答案；不为“独特”否定有意采用的类型化人物。
- 同一经历可以产生不同策略，比较哪种更能支持当前故事；不强制人人有创伤。
- 轮廓测试可用于远景识别；原作需要相似人物时如实保留，也可通过声音、位置或动作区分。

## 六、表演试读法

本节帮助确定剧本中的表演方向，不生成图像或视频投喂提示词。

1. 通读角色目标、阻力和关系位置。
2. 需要比较方案时提出少量差异明确的方向，说明各自要验证什么。
3. 选择能实际表演的试读台词，避免只背设定。
4. 记录说话方式、倾听反应、身体策略和情绪转折。
5. 按既有授权或用户选定结果写入表演备注；视觉身份与镜头试拍分别交给相应制作技能。

更换角色方向时重新检查目标、阻力和策略，不能只换形容词。

## 七、视觉身份边界

剧本记录影响故事的年龄、体态、生活痕迹、服装功能和动作习惯，不规定图像模型的禁词、皮肤词、焦段或摄影风格。完整外观、稳定锚点和模型适配由 `zion-assets` 处理；人物进入分镜后使用资产 ID 与版本，无需跨文件逐字复制整段描述。

## 八、修订与影响范围

改动不是全都需要通知下游。按影响面分三类，处理方式不同：

| 类型 | 例子 | 处理 |
|---|---|---|
| 措辞级 | 错字、语气微调、同义替换 | 不改版本；不进受影响场次清单 |
| 场内级 | 某场的对白、动作或调度改变，但人物与事件结果不变 | 递增版本或标记改动，列出该场 |
| 结构级 | 增删场次、改变人物关系、动机、结局或信息顺序 | 递增版本，列出受影响场次及其下游影响 |

- 修订后递增 `script_version`，列出受影响场次，供资产、分镜与 QA 判断旧交付是否失效（见 `zion-script` 主文件的交接规则）。
- 场次增删时**不重用已发出的 `scene_id`**：删除的留空，新场取新号。重用会让下游把两个不同的场认成同一场。
- 判断下游影响的顺序：改了人物外观或身体状态 → 资产要重制；改了场次结构或信息顺序 → 分镜要重做；改了台词文本 → 配音与口型要重做。三类都要在清单里点出来，不停留在"已修改"。
- 改写对白而动机、关键信息与结局未变时，按场内级处理（见 [对白设计与诊断](04-dialogue-design.md) 的诊断纪律）。

## 九、交接与自检

- 人物的目标、阻力、策略和关系位置是否足以支持当前故事？
- 说话与行动是否符合具体处境；有意的类型化或相似性是否得到保留？
- 关系是否影响选择、信息或对白，而非孤立标签？
- 年龄、体态、服装等是否只写本阶段需要的部分？
- 进入下游制作时，`project_id`、`script_version` 与稳定 `scene_id` 是否可追踪，修订影响范围是否明确？
