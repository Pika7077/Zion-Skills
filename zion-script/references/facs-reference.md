# FACS 可选参考

仅在用户明确要求 AU，或相似表情间的细微差异需要精确描述时读取。普通剧本使用自然语言即可。

FACS 描述可见的面部动作；动作编码还需要结合情境解释，不能直接当作内心情绪的证明。标准编码依据及训练要求见 [Paul Ekman Group：FACS](https://www.paulekman.com/facial-action-coding-system/)（核验：2026-09-21）。

## 少量常用动作

| 编码 | 自然语言描述 |
|---|---|
| AU1 | 眉内侧上提 |
| AU2 | 眉外侧上提 |
| AU4 | 眉部下压并靠拢 |
| AU6 | 面颊上提，眼周外观随之变化 |
| AU12 | 嘴角向上、向外拉 |
| AU15 | 嘴角下拉 |
| AU17 | 颏部上提，带动下唇 |
| AU23 | 唇部收紧 |
| AU24 | 双唇压合 |
| AU25 | 双唇分开 |

动作对应参考 [Lien：Facial Expression Recognition System Overview，图 4](https://www.cs.cmu.edu/~jjlien/Thesis/ch2systm.pdf)（核验：2026-09-21）。这不是完整编码手册；新增编号时查权威资料，不凭记忆补表。

## 创作中如何使用

1. 先写希望被看见的动作与触发，例如“听到名字后，眉内侧上提，嘴角仍压住”。
2. 只有编码有助于沟通时附上已核验 AU；明确强弱、先后或单侧变化，不堆整套情绪配方。
3. 同一动作组合可承载不同含义。眼周是否参与笑容可以作为外观差异，不能单凭 AU6 / AU12 判定真假情绪。
4. 混合表情需保证动作可同时成立，也可以通过先后变化呈现冲突；不强制每个表情混合两种情绪。
5. 保留自然语言描述，实测目标模型是否理解编码；不能宣称 AU 码在任何文生视频入口都有效。
6. 身份参考图、构图、声音和状态继承按当前制作需要提供，AU 不能替代它们。

例：角色努力维持笑容。嘴角仍上提（AU12），听到最后一句时眉间逐渐收紧（AU4），随后把目光移向门口。这里只设计可见变化，情绪由台词与情境共同建立。
