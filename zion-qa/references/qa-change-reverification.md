# 改动后复验

适用情形：交付物已经过一轮验收，随后在授权范围内做了修改。这时只检查改动处不够——一处改动会沿引用链带动多处，只看改动处等于把问题漏给下游。

## 一、三步

### ① 局部验证

改动处自身是否达到了修改目的。检查对象是这次真正被改动的字段、句子或镜头，包括它与直接相邻内容的衔接（上一句、下一镜、前后场）。

### ② 联动检查

沿引用链找这次改动的下游影响。对每一项给出结论：受影响，或不受影响及理由。**“看起来无关”不构成不受影响的理由**——要说出为什么无关（例如该字段不被任何下游引用、改动只涉及措辞不改数值）。

按交付物类型逐项过，不适用的项说明不适用：

| 交付物 | 联动项 |
|---|---|
| 剧本 | 人物状态与关系、信息揭示顺序、伏笔与回收、场次时长、结尾完成度 |
| 资产 | 稳定 ID 与版本、状态与真实文件、跨镜复用的身份特征、与分镜引用的一致性 |
| 分镜 | 时间码首尾相接与总时长、连续状态（位置、持物、动作阶段、伤情）、组尾末态与下一组起手、接缝方式、资产引用与版本 |
| 生成提示词 | 字数与时长预算、声音与对白归属、主体与指代的清晰度、正负向指令是否互相抵消、素材用途标注 |
| 跨文件 | 手册、检查清单、其他技能中的判据是否与改动后的口径一致 |

改了判据或口径时，联动检查的范围要扩到**所有引用该判据的文件**，而不只是当前这一份。

### ③ 全量复核

按交付范围把原有的检查项重跑一遍，不只重跑改动处。改动可能让原本通过的项变得不成立（例如缩短一个镜头后，对白容量、动作可读性与接缝末态同时受影响）。

## 二、报告

修改类任务交付时附一份可核对的结果，包含：

- 改动清单：改了什么、位于哪里、依据是什么。
- 联动检查结论：逐项给出受影响或不受影响及理由。
- 全量复核结论：按检查项给出通过、问题或未验证。
- 未验证项：因材料缺失或依赖实际生成而无法判断的部分，明确列出，不写成通过。

未附联动结论的修改视为未完成复验。

## 三、边界

- 只复验改动处，或把联动检查写成“无影响”而不给理由，都算未完成。
- 不为保住“已通过”的结论而回避复验；改动后新增的问题按正常分级报告。
- 复验发现的问题，若修复会改变受保护的故事方向或业务规则，回到待定与询问，不自行决定。
- 复验范围随改动影响面变化：措辞级改动不必重跑全量，但只要动了数值、时长、状态或判据，就要按②③执行。
- 复验结果不等于生成结果验收；依赖实际生成才能判断的部分仍标为未验证。

## 四、与四种模式的关系

改动复验借用既有模式的检查方式，不新增模式：改动落在结构、ID 或跨文件状态时按结构与一致性模式执行；落在分镜或提示词时叠加上可生成性检查；改动涉及剧本正文时叠加上盲读检查。用户已授权修复时，修复与复验一次完成，并给出上面的报告。

## 五、自检

- [ ] 改动处自身已验证，包括与相邻内容的衔接
- [ ] 联动项逐项给出结论，不受影响的项写了理由
- [ ] 改动涉及判据或口径时，已检查所有引用该判据的文件
- [ ] 全量复核按交付范围重跑，不只重跑改动处
- [ ] 报告含改动清单、联动结论、全量结论与未验证项
- [ ] 依赖实际生成才能判断的部分标为未验证，未写成通过
