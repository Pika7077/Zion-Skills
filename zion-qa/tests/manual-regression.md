# zion-qa · 人工回归

按请求与材料对照实际行为；平台、图片和视频缺少真实证据时只判断可核实部分，不把静态复核写成生成实验。

1. “校验这批分镜文件。”自动选择结构与一致性模式，按文件实际规格检查；不套品牌、会议室、植入或对白字数规则。
2. “用新观众视角看看能不能看懂。”输出人物、关系、动机、时间和因果障碍，定位到集或场。
3. 一个无复仇、无时限、无下一集钩子的独立抒情短片，只要信息与表达目标可理解，就不因缺少“气爽急追”判失败。
4. 用户已提供材料且只说“检查”，直接选适用模式并报告，不要求用户先选模式或重新授权只报告。
5. “检查一下”但没有任何可识别材料时，先问材料范围；不能自动扩大到整个工作区。
6. “这段提示词能直接投喂吗？”检查目标模型、入口、组自足、容量、状态和冲突。仅采用默认模型时注明默认，并保留相关能力/入口待核验项，不能承诺可直接投喂或已生成验证。
7. 三人同框、镜面构图、复杂接触不因旧人数上限或反射禁令判 FAIL；应给出实际风险证据。
8. brief 明确品牌白名单、对白上限或场景禁令时，按来源检查。无法核验的平台规则写未知，不伪装成违规。
9. 用户已说“检查并修复”时，定位后在授权范围内完成修复及复验，不要求另说“你定”；改变受保护的结局或业务要求仍需澄清。
10. 盲读发现指代不明且已获修复授权时，可以改正文后复验；不能把新增设定说明当成观众已经理解。
11. 跨模式请求分别给结论，不以结构通过替代可读性、投喂或结果通过。
12. 同批已登记冻结段出现未经登记的第二种写法时，报 WARN 并核对版本；不直接判 FAIL。
13. 冻结段混入景别或主体占比时，定位变量污染；独立投喂块仅写“同上风格”而缺少所需上下文时，指出不自足。
14. 用户要求跃起瞬间的海报时，不因动作词本身报 WARN；身份设定图若同一姿态遮住必要面部/服装信息，则指出用途冲突。
15. 基调与事件的有意反差有叙事依据时可保留；无依据的矛盾则定位具体条目，不整体判失败。
16. 当前剧本 `script_v4`，资产或分镜仍基于 `script_v3` 时，报告源版本失配及受影响场次。
17. 正式分镜引用未登记资产、缺失版本、candidate/deprecated 等非准入状态、approved 无真实 files 或 uploaded 无 target_reference 时阻断；即使只检查导演稿也不能省略状态条件。生成提示词使用 approved 或将未上传资产伪装成入口引用时也阻断。
18. 一个视频只有头尾可裁去的坏帧且主体可用时，按目的评估后期修复或可用片段，不判整条废弃。
19. 同类瑕疵发生两次时，查看证据、指令、资产和入口后判断原因；不自动 Rewrite，也不自动建议无上限重摇。
20. 续接已经超过三层但当前内容满足要求时，不因层数拒收；以实际身份、状态和接缝质量判断。
21. 单张图片验收定位到可见区域，不套视频时间连续性或强制完整批次报表。
22. 只有三张抽帧或无音频时，不能声称全片与音画同步通过；低清预览不能证明最终文字细节正确。
23. 没有 ledger CLI 时仍能用简表交付；不调用不存在的 `amend-gen` 或 `--draft`。
24. 结果可以后期修或当前入口局部编辑时，说明两种处置的范围和条件；未经授权不实际生成、上传或消耗费用。
25. 仅安装 QA 时，能独立检查已有文件并交付证据与建议；上游制作能力缺失时准确列待办，不假称已转交。
26. “把这两处改掉再看一遍”属修改类任务：交付改动清单、逐项联动结论、全量复核结论与未验证项；只复验改动处算未完成。
27. 联动检查写成“其它地方无影响”而不给理由时不合格；应说明为什么无关（如该字段不被下游引用、改动只涉及措辞不改数值）。
28. 改动涉及判据或口径时，检查范围扩到所有引用该判据的文件（手册、检查清单、其他技能），不只看当前这一份。
29. 缩短一个镜头后，同时核对该镜的对白容量、动作可读性、组尾末态与下一组起手是否受影响，并给出结论。
30. 措辞级改动不必重跑全量；但只要动了数值、时长、状态或判据，就按局部验证、联动检查、全量复核三步执行。
31. 复验发现的问题若修复会改变受保护的故事方向或业务规则，保持待定并询问，不自行决定。
32. 复验结果不等于生成结果验收；依赖实际生成才能判断的部分标为未验证，不写成通过。
33. **三套结论不混写**：P0/P1/P2 表示影响，FAIL/WARN/INFO 表示投喂准备度，Keep/Fix/Edit/Re-roll/Rewrite 表示结果处置；同一 P1 可能后期修或重写，不能建立机械一一映射。
34. **剧本场次验收**：“这场只是两人聊背景。”检查进入—退出差值、当场目标、策略、阻力和转向；氛围或等待场若改变观众体验仍可成立，不以缺少争吵判失败。
35. **类型按项目启用**：悬疑检查线索公平和揭晓回指，喜剧检查前提—偏差—反应，恐怖检查威胁规则与余波；无明确类型的实验短片不套这些机制。
36. **资产分类验收**：生物检查关节、尺度和动作不变量；载具检查出入口、可动结构与活动范围；不能只因都有 asset_id 就判内容完整。
37. **精确文字的两层证据**：图形资产的视觉版式可以通过，但准确文本若没有可编辑源或最终尺寸复核，文字项仍为未验证或问题；不以整体好看替代逐字正确。
38. **VFX 与合成**：烟雾、光效或角色合成检查发生源、前后景、遮挡、边缘、影子/反射与交互光；没有真实层或成片时不能宣称合成通过。
39. **时间域缺陷定位**：身份漂移、纹理沸腾、无动机闪烁或边缘抖动要给时间段和证据；单帧异常不自动代表整段，正常播放无感也不能覆盖关键接触处的逐帧问题。
40. **声音专项**：定位说话者、画内/画外归属、口型偏差、对白可懂度、重复、削波、音乐遮蔽和底噪断裂；无音频时全部标为未验证。
41. **技术规格有来源**：分辨率、编码、码率、响度、声道、安全区和闪烁是否通过，只能按已提供的交付规范和真实文件判断；缺少任一方时列待验证。
42. **颜色不能是唯一信息通道**：项目要求无障碍或操作可读时，阵营、状态、按钮只靠颜色区分应提出形状、位置、文字或纹理辅助；不擅自改变已确认的叙事色彩。
43. **无声观看是条件项**：只有项目要求静音可理解时才检查关键叙事是否只依赖声音；不把所有作品一律改成满屏字幕。
44. **本地化复核**：多语言版本检查文字长度、断行、阅读方向、配音时长、口型依赖和文件映射；只换字幕文件名不算完成。
45. **来源登记不做法律结论**：外部素材来源未知时报告 `rights_status=unknown` 和待补证据；不自行判定侵权或可商用。
46. **用户声明与确认分开**：用户声称有权使用可作为 `user-asserted` 证据；没有独立材料时不能升级为 `confirmed`。
47. **制作状态不覆盖权利状态**：资产可以 `uploaded` 但权利仍 `pending`；制作可投喂与正式发布可交付分别给结论。
48. **矩阵按需使用**：检查一张人物设定图时，只选图片与人物资产相关项；不为完整报告附上剧本、声音、字幕和多平台空章节。
