# 场景一致性与状态阶梯

场景不是背景板，是**压力容器**与**可复用地理**。本档解决四件事：场景要锁定什么（地理锁）、同一场景在不同戏剧状态下如何有依据地变化（状态阶梯）、同一场景的多个观察方向如何对齐（跨 View 光线）、元素过多时如何取舍（一致性优先于丰富度）。

空间拓扑、出入口、固定锚点、材质与光源的提取规则见 [资产一致性](14-asset-consistency.md) 与 [资产提示词](asset-prompt-builder.md)；本档补的是**跨镜、跨集、跨方向的一致性维护方法**。

## 一、场景闸门：先问五个问题

场景设计完成前逐条核对。任一条答不上来，场景就还只是"好看的背景"，不能进入制作：

1. **谁控制入口、出口、座位、桌、床、窗、门槛？** 空间里必须有一个可指认的控制点。
2. **谁被挡住、被暴露、被逼到角落、被抬高、被注视，或被迫穿过整个房间？** 没有位置差就没有场面调度。
3. **哪个物件可以被递出、签署、揭示、拒收、打破或藏起？** 交接物件是短剧最经济的信息载体。
4. **在 9:16 画幅里，前 3 秒能读出什么？** 权力关系必须在小屏首帧可读。
5. **下一镜／下一组必须继承哪个可见状态？** 答不出这一条，跨镜连续性就没有锚。

**判定**：如果这个空间无法承载羞辱、救援、背叛、揭示、亲密、威胁或反转中的任何一种，它还不具备投产条件。**不要设计漂亮的空房间**——每个被选中的锚点都要能帮角色行动、失败、躲藏、碰撞、发现或改变。

### 场景必须承载的权力机制

空间的"高级感"不能替代权力机制。每个场景先指定它服务什么权力动作：

| 权力领域 | 场景类型 | 固定锚点 | 动作杠杆 |
|---|---|---|---|
| 企业／权力核心 | 总裁办公室、董事会议室 | 玻璃幕墙、长桌、城市窗景、座椅等级、铭牌 | 解职、表决、收购、合同揭示 |
| 家族财富／继承 | 家族办公室、遗产律师所 | 信托卷宗架、封口信封、厚书桌、档案柜 | 签署、宣读遗嘱、资产冻结 |
| 公权力／司法 | 法院走廊、检察发布厅、律所 | 国徽、话筒线、案卷夹、旁听席 | 传票、公开指控、认罪协议 |
| 医疗／保险 | 医院走廊、病房、理赔办公室 | 床栏、监护仪、冷光灯、工牌台、红章 | 手术延误、拒赔、诊断揭示 |
| 教育／阶层 | 招生办公室、奖学金走廊、捐赠晚宴 | 奖杯墙、校徽、招生档案、捐赠名录 | 录取、奖学金威胁、公开羞辱 |
| 居住区／社区规训 | 干净的街道、门前草坪、社区活动室 | 信箱、白栅栏、违规通知单、修剪整齐的草坪 | 罚款、表决、驱逐压力 |
| 信仰／慈善 | 联谊厅、慈善办公室、礼拜堂侧室 | 公告栏、捐赠台、十字架、认捐卡 | 声望暴露、拨款否决 |
| 宴会／典礼 | 宴会厅、楼梯平台、服务通道 | 水晶灯、香槟台、舞台、侧门 | 身份揭示、公开拒绝、秘密录音 |

**每一档都要有可动的工作面**（桌角、床栏、讲台、文件夹托盘、登记台）。没有工作面，递出、签署、揭示这类动作就没有落点。

### 角色—场景配对规则

**每个核心角色至少有一个他控制的场景，和一个他失控的场景。** 如果一个场景不属于任何人，它就不会产生戏剧。分配时按场次表核对，不做平均分配。

## 二、竖屏动线（9:16）

竖屏空间的失败多半不是"不好看"，而是**没有动线**。宽横厅照搬进 9:16，人物会无处可站。

| 层 | 作用 | 必须写清 |
|---|---|---|
| 前景压迫物 | 建立框景与局部遮挡 | 门框、桌沿、栏杆、文件夹、托盘、话筒架 |
| 中央演员通道 | 主体进入、停下、转身、穿过或被挡住的那条竖向路径 | 通道本身保持无遮挡 |
| 背景权力锚点 | 交代这是谁的场 | 城市窗景、校徽、会议长桌、奖杯墙、国徽、病床监护仪 |
| 门槛轴 | 控制到达与离开 | 门、电梯、走廊、楼梯、帘幕、侧入口 |
| 交接区 | 物件传递发生的具体承载面 | 桌角、床栏、讲台、边几、文件夹托盘、登记板 |

竖屏资产与镜头提示词可直接用这类短语：

```text
竖屏 9:16 动线，中央通道清的、前景桌沿压住下三分之一、门轴在人物身后可见、背景权力锚点保持可读
```

```text
双人对峙动线，强势者靠近桌与光源，被困者靠近门口，文件交接区在两人之间
```

**判据**：把竖屏参考图当成电影横构图来设计，是竖屏短剧最常见的场景错误。宽建筑不等于可用空间。

### 净空与体量：与动线并列的第三类空间事实

动线管"人往哪走、被什么挡住"；**净空与体量管"人在这块空间里还剩多少余地"**。低矮、逼仄、被压住的处境常用来表达焦虑、被困或身份落差——这类处境必须先作为可登记的空间事实写下来，否则分镜只能临场形容，出图也没有锁定项。

| 项 | 写什么 | 例 |
|---|---|---|
| **头顶净空** | 站立者能否直起：`可站直` / `需低头` / `无法站直` | 桥下检修位、车厢内、阁楼、地下室矮梁 |
| **身体余量** | 转身、抬臂、后退各需要多少空间；哪些动作在这块空间里做不出来 | 后排座椅顶住膝盖；两人并排时肩膀相碰 |
| **可退距离** | 从当前站位到最近遮挡物或墙的余量 | 背靠墙两臂；无处后退 |
| **体量与比例参照** | 人物与该空间的相对关系，用已在场的中性参照说明 | 头顶到梁的距离约一掌；门框高于人物一头 |

**与动线的分工**：动线决定"能不能走通"，净空与体量决定"站在这里是什么感受"。两者都要登记——只写动线不写净空，会得到一条能走通的通道和一个失去压迫感的空间。

**随状态变化**：净空会随场景状态改变（灯光支架落下、纸箱堆高、门口被堵），这类变化按 §三 的状态阶梯登记，不另建场景。

**进提示词时**只写与本镜任务有关的那一项（"头顶横梁压住画面上缘，人物需侧身通过"），不把四项全写进去。

## 三、场景状态阶梯

**同一个房间不能在大事件之后干净复位。** 场景需要状态变化，且变化必须有可见证据。

| 状态 | 用途 | 可见规则 |
|---|---|---|
| `S0_常态` | 冲突前建立地点 | 干净、功能正常、社会秩序正常 |
| `S1_压力前置` | 紧张开始 | 门半开、文件夹摊在桌上、硬光、通路被挡 |
| `S2_羞辱` | 公开羞辱或胁迫 | 角色被困在边缘、旁观者可见、关键物件在压制者手里 |
| `S3_揭示` | 证据或身份翻转 | 屏幕／文件／信封移到画面中心，光落到证物上 |
| `S4_余波` | 后果留存 | 空椅、洒出的酒、散落的纸、灯光变暗、门的状态改变 |
| `S5_权力反转` | 原本弱势的一方控制了空间 | 新的中心位、更干净的光、物件归属转移 |

**S 编号不是必须填满的六档**，只在剧情真实推进到该状态时使用。但**一旦用过，后一个状态必须继承前一个状态的可见痕迹**——这正是短剧观众判断"剧情有没有真的发生"的依据。

### 状态登记格式

```text
@场景基线身份 =
S0_常态 =
S1_压力前置 =
S2_羞辱 =
S3_揭示 =
S4_余波 =
S5_权力反转 =
受保护锚点 =
允许变化 =
禁止漂移 =
```

- **受保护锚点**：门轴、窗墙、桌的朝向、主要分区——任何状态下都不许动。
- **允许变化**：门开合、桌面物品、地面痕迹、灯光状态、椅子的位置。
- **禁止漂移**：不得改变固定地理、不得凭空复位、不得改变光源来源。

**与 `zion-storyboard` 的分工**：本档登记的是**场景自身跨镜可复用的状态**（属于资产层事实）；具体某一组镜头继承哪个状态、状态在哪一镜切换，由 `zion-storyboard` 的镜头连续性处理。两侧的 S 编号必须指向同一个状态定义。

## 四、跨 View 的光线对齐

同一地点通常会按观察方向拆成多块参考板（同一条走廊分别做朝北与朝东两块）。这些板会被同一场戏的正反打互相剪接，**所以它们之间也要能对上**。

**口径**：同一地点在同一时间／天气状态下，各个 View 必须共享同一套主光来源、色温关系与光比方向。差异只能来自已记录的成因，并写进对应的状态差异。

失效机制是不对称的：地理错位一眼能看出，**色温和主光位不一致却常常各自都"很好看"**，只在两块板被剪在一起时才暴露成"两个不同的时间"或"两个不同的房间"。逐块单独审查抓不到它，必须把同一地点同一状态下的板**并排比**。

### 对齐清单（同一地点 + 同一时间／天气状态内）

- **主光来源**：是同一扇窗、同一组灯具、同一片天空吗？换 View 只改变我们从哪一侧看它，不改变它是什么。
- **色温关系**：冷暖主次是否一致。某块板把暖色实用灯升为主光、别的板把它压成次要，就是一次未记录的变化。
- **光比与暗区方向**：亮暗落差的量级，以及暗区落在空间的哪一侧。
- **实用灯开关状态**：同一状态下不能一块板亮着吊灯、另一块板熄着。

**允许且应当记录的差异**：View 朝向决定的逆光／顺光关系、遮挡造成的局部落影、朝窗与背窗的自然亮度差。这些是同一光源在不同观察方向下的正常表现，写清来源即可，不需要拉平。

### 需要改光时走状态差异

时段推进、停电、开灯、天气转变，都算**新的时间／天气状态**。同一地点的**所有**已有 View 都要一起交代如何变化，不能只改被用到的那一块。

```text
loc_某某_基准 →
loc_某某_朝北_日间 =
loc_某某_朝东_日间 =
loc_某某_朝北_夜雨 =   （与日间共用主光来源，仅记录变化项）
```

**与 `zion-storyboard` 的分工**：本档管**同一状态下跨 View 的板间对齐**（资产层）；同场景内的跨镜继承律、反向机位与光的演变由 `zion-storyboard` 的光影系统档负责。两侧的口径必须一致——场景板之间对不上，镜头之间必然对不上。

## 五、空场政策

场景空镜保持已确认的布局、朝向、固定锚点、材质与光向。默认不带角色，以保持作为地理参考的复用性。

| 政策 | 含义 |
|---|---|
| `required` | 不出现剧情角色、临时群众或叙事动作；固定家具与功能设备保留 |
| `preferred` | 以空场为主，允许不具身份的尺度提示，但不得妨碍地理读取 |
| `not_required` | 可有人群或工作痕迹，但不能编造具体角色事件 |

**冲突判定**：`required` 与"主角站在入口"这类演员要求显式冲突。确需人物作尺度参照时，先改政策，或改用不具身份的中性参照。

**尺度参照**：参照物不得引入剧情角色，也不得与空场政策冲突。道具可用带刻度的底座、常见手掌尺度或已知功能结构作参照——而不是只写"巨大"或"小巧"。

**边界**：不得为氛围新增剧情事故、封锁出口或移动固定结构。"压抑、危险、温暖"必须翻译为已有依据的空间选择：通道狭窄感、光比、材质反射、空气状态、色温关系。

## 六、环境叙事层

好的场景不需要台词就能讲故事——通过物件摆放、磨损痕迹、空间状态暗示"这里发生过什么"。

### 五层模型

| 层 | 内容 | 载体示例 |
|---|---|---|
| 1 功能 | 这个空间是做什么的 | 厨房、办公室、礼拜堂 |
| 2 居住者 | 谁在这里生活／工作 | 书架上的书暗示主人身份 |
| 3 状态 | 当前正在发生什么 | 未吃完的饭＝匆忙离开 |
| 4 历史 | 过去发生过什么 | 墙上褪色的照片＝失去的人 |
| 5 预兆 | 即将发生什么 | 窗外压低的云＝风暴将至 |

层次越靠后信息量越大，也越容易被滥用。**一场戏用 1–2 层即可**，不要把五层全部塞进一张图。

### 物件类型与叙事功能

| 物件类型 | 叙事功能 | 示例 |
|---|---|---|
| 日常物件 | 暗示居住者性格 | 排列整齐的鞋＝强迫；散落的酒瓶＝堕落 |
| 时间物件 | 暗示时间流逝 | 日历停在某日＝创伤；积灰厚度＝废弃年限 |
| 伤痕物件 | 暗示冲突发生 | 墙上的拳印＝暴怒；刀痕＝暴力 |
| 缺席物件 | 用空缺暗示存在 | 餐桌上多出一副碗筷＝等待／思念 |
| 入侵物件 | 暗示外力介入 | 窗上的弹孔＝战争；封条＝查封 |
| 自然入侵 | 暗示被遗弃 | 地板长出的青草＝长期无人 |

### 三条纪律

1. **每个场景至少放 1–2 个叙事物件**，且必须能被画出来（不是"有氛围感的小物"）。
2. **物件要"自然"而非"刻意"**——观众应该感觉是自己发现的，而不是被指给你看。
3. **磨损与污渍要符合使用逻辑**：高频触摸区域先磨损。门把手、桌沿、扶手比墙面脏得快；反过来写会被读作贴图错误。

**与视觉母题的分工**：本档管**场景内部**的环境叙事（一次性的空间信息）；跨场次反复出现的**视觉母题**由 `zion-storyboard` 的视觉母题档负责。一个物件要成为母题，必须在多个场次复现并每次带来新信息——只出现一次的，属本档。

## 七、场景视频可用性预检

一张场景参考图不等于可以直接进视频。核心场景要用 5–10 秒的**运动试镜**检验，再贴标签。

### 运动测试项

- 角色从主入口进入并停在中央通道。
- 角色从门口走到桌／床／讲台。
- 一个角色在门槛处挡住另一个角色。
- 文件夹、信封、手机、证件、戒指或登记板在交接区移动。
- 摄影机推进；背景锚点保持稳定。
- 两人对峙；权力位置保持可读。
- 下一镜能继承门的状态、物件位置、光线和表面痕迹。

### 标签

| 标签 | 含义 |
|---|---|
| `scene_video_ready` | 布局、光、锚点与演员通道能承受简单运动 |
| `needs_layout_lock` | 门、桌、床、窗或桌的位置漂移 |
| `needs_light_lock` | 光向或色温变化过大 |
| `needs_prop_lock` | 叙事物件消失、变形或跑到错误的区域 |
| `image_only` | 可用作氛围／参考，但不够稳，不做视频基础 |
| `reroll_scene` | 静帧本身缺动线或叙事压力，需重做 |

### 预检记录

```text
asset_id =
基准场景图 =
运动测试 =
布局稳定性 =
光线稳定性 =
道具稳定性 =
动线可读性 =
连续性状态 =
可用性标签 =
修复指令 =
```

**边界**：本档只做**资产层的静态可用性判断**，不声称视频已经生成或运动已经成功。实际视频结果由生成与验收环节判定。

## 八、常见失败与修复

| 失败 | 成因 | 修复 |
|---|---|---|
| 样板间漂移 | 堆砌奢华、大理石、水晶灯、"电影感" | 点名具体权力功能：会议室、理赔办公室、招生办；补工作面与制度性道具 |
| 空荡好看的房间 | 只有氛围，没有动线 | 补入口、门槛、中央通道、交接区、冲突位置 |
| 横构图画幅漂移 | 宽建筑不等于竖屏可用 | 明确 9:16 动线、中央通道、前景压迫物、背景锚点 |
| 门窗漂移 | 基础布局未锁定 | 记录门轴、窗墙、桌的朝向与受保护锚点 |
| 道具消失 | 把道具当装饰 | 让它成为有归属、有承载面、有动作的叙事物件 |
| 光线复位 | 没有场景状态台账 | 追踪 S 状态、光源、门窗状态与痕迹 |
| 跨 View 像两个房间 | 各板各自选主光与冷暖主次 | 并排比同组板，差异必须有成因并写进状态差异 |
| 越画越漂移 | 元素数量超出可维持范围 | 按取舍顺序删装饰性陈设，保住窗位、光向、地面质感三项 |
| 同一个地方认不出 | 简化时删掉了核心质感 | 把"元素数量"与"材质光向精度"分开——可以少物件，不能少材质描述 |
| 只对得上名字，对不上地方 | 缺制度性细节 | 补国徽、社区通知、奖杯墙、招生档案、理赔红章、工牌台、规划图 |

## 九、场景板卡字段

场景资产卡在本档字段基础上，补以下一致性专用字段：

| 字段 | 用途 |
|---|---|
| `space_type` | 空间类型与整体尺度 |
| `narrative_task` | 这场戏要建立／揭示／施压／转折／释放／回收什么 |
| `power_mechanism` | 谁控制入口、座位、桌、床、讲台、文件或光 |
| `vertical_lane` | 前景压迫物／中央通道／背景锚点／门槛轴／交接区 |
| `clearance` | 净空与体量：头顶净空（可站直／需低头／无法站直）、身体余量、可退距离、体量与比例参照 |
| `fixed_anchors` | 不可移动物及其**相对关系**（不是物件清单） |
| `view_set` | 已制作的观察方向，以及各自所属的时间／天气状态 |
| `light_source_shared` | 同组 View 共用的主光来源与色温关系 |
| `state_ladder` | 本场景已使用的 S 状态与各自可见证据 |
| `protected_anchors` | 任何状态下都不许动的项 |
| `allowed_changes` | 状态之间允许变化的项 |
| `forbidden_drift` | 明令禁止的漂移 |
| `narrative_objects` | 1–2 个叙事物件及其所属层（功能／居住者／状态／历史／预兆） |
| `empty_stage` | `required` / `preferred` / `not_required` |
| `readiness` | `scene_video_ready` 或待修标签 |
| `before_after` | 本场景进入时的状态与离开时的状态 |
| `core_textures` | 窗户位置、光线方向、地面质感三项核心质感的取值——简化时不许删 |
| `plan_view` | 俯视空间位置图的结论摘要（出入口、窗与主光、通道、交接区、各 View 观察位） |

### 地理写法

**用相对关系，不用物件清单。**

- 好：`从卷帘门向内看，检修台沿右墙延伸，尽头唯一安全门正对通道`
- 差：`有铁门、桌子、灯、箱子、柜子`

**位置必须用世界坐标表述**，不用随镜头变化的"画面左边"：写"窗边长桌的门侧"，不写"画面左边"。镜头稿负责记录摄影机轴线与画面方向。

**先画文字地图**：从哪个入口看向哪个方向，前／中／后景分别是什么，关键锚点在彼此的哪一侧，演员可能从哪里进出。只有与识别、调度或连续性有关的结构进入提示词。

## 十、场景取舍：一致性优先于丰富度

**场景设计的难点不是丰富度，是一致性。** 元素越多，跨镜、跨集、跨 View 需要维持的东西越多，漂移概率按元素数量叠加。缺元素只是不好看，漂移会让观众出戏。

### 取舍顺序

**先定取舍，再进提示词。** 一个场景的候选元素按以下顺序过筛：

| 顺序 | 元素 | 处置 |
|---|---|---|
| 1 | 窗户位置、光线方向、地面质感 | **必保**——三项核心质感，任何精度下都不删 |
| 2 | 固定锚点、出入口、交接面 | 必保，但可减少数量至可指认 |
| 3 | 叙事物件 1–2 个 | 必保（见第六节） |
| 4 | 装饰性陈设、背景小物、纹理细节 | **可删**——优先删这一层 |

**判据**：删掉之后，观众还能不能读出这是同一个地方、光源从哪来、人在哪站？能，就可以删；不能，说明删的是必保项。

### 三项核心质感不可删

这三项是跨镜可读性的下限，简化时必须留住，且必须写进场景板卡：

- **窗户位置**——决定主光从哪来，删了或移位，光线就失去依据，跨 View 必然对不上（见第四节）。
- **光线方向**——决定所有镜头的亮暗结构与阴影方向，是连续性最容易穿帮的一项。
- **地面质感**——承受影子、脚印、洒落物、磨损痕迹，是状态阶梯（第三节）的落地载体；地面一抽象，S 状态的痕迹就无处依附。

简化可以删掉"元素数量"，不能删掉"材质与光向的描述精度"。**去掉五个箱子，不能去掉地面是水泥还是木地板。**

### 俯视空间位置图

**文字地图不够时，补一张俯视位置图。** 它是场景板卡的附属产物，不进画面、不出提示词。

**什么时候必须画**：空间有两个以上入口、有拐角或隔断、有超越单一观察方向的遮挡关系、有需要明确相对方位的对峙或走位。单一开间、正面拍摄的小场景可省。

**画法**（示意，非像素规范）：

```text
        [窗]
         │
   ┌─────┴─────┐
   │           │
[门]── 中央通道 ──[桌]──[安全门]
   │           │
   └───────────┘
```

**必须标出的项**：

| 项 | 为什么 |
|---|---|
| 入口／出口及其开门方向 | 决定谁能在什么时候进来 |
| 窗与主光来源 | 跨 View 对齐的依据（第四节） |
| 中央通道与前景压迫物 | 9:16 动线（第二节） |
| 交接区与承载面 | 物件传递的落点 |
| 摄影机各 View 的观察位与朝向 | 与 `view_set` 字段对应 |
| 角色可站区与不可通行区 | 排除穿帮走位 |

**边界**：俯视位置图是**内部核对工具**，用于对齐 `fixed_anchors`、`view_set` 与镜头轴线的相对关系。它是资产层的空间事实登记，不是分镜稿，不含镜头顺序与时长。

### 用完整空间设定驱动自动拆分镜

把**完整空间设定**（场景板卡字段 + 俯视位置图结论）作为输入交给下游，可以帮助自动拆出镜头并保持场景关系与质感一致。这属于**下游消费方式**，不是本档的输出职责。

**口径边界**：

- 本档产出的是**空间事实**：`fixed_anchors` 的相对关系、`view_set` 各方向的观察位、`light_source_shared` 的主光与色温关系、`state_ladder` 的可见证据。
- 自动拆分镜由 `zion-storyboard` 的分镜档一侧的专业流程处理，本档不定义镜头顺序、时长与切点。
- **未记录的空间事实无法被下游继承**——自动拆分镜不会补上你没写的东西，缺的锚点只会被自由发挥。空间设定写得越完整，拆分镜的一致性越好；反之，自动拆分镜会把缺口放大成漂移。

**与 `zion-storyboard` 的分工**：本档负责把空间设定写到"可以被下游直接引用"的完整度；镜头拆分、机位选择与轴线由 `zion-storyboard` 负责。两侧引用同一套 `fixed_anchors` 与 `view_set` 定义，不各写一份。
