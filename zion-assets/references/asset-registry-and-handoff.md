# 资产登记与交接

人物、场景、道具和其他资产的统一登记规则。资产提示词、候选图和已绑定引用是不同状态，不能混写。

## 一、稳定 ID

建议使用可读且不依赖文件顺序的 ID：

| 类别 | 前缀示例 | 记录重点 |
|---|---|---|
| 人物 | `char_` | 身份锚点、服装/状态、音色、别名 |
| 场景 | `loc_` | 空间拓扑、出入口、固定锚点、光源、时间状态 |
| 道具 | `prop_` | 轮廓、尺寸、材质、功能、文字、持有者、状态 |
| 服装 | `cst_` | 所属人物、结构、材质、穿着阶段、损伤/污渍 |
| 生物/载具 | `ent_` / `veh_` | 比例、结构、动作能力、状态 |
| 图形/特效/声音 | `gfx_` / `vfx_` / `aud_` | 用途、格式、触发方式、版本 |

项目已有命名规则时继承项目规则，不强制使用上述前缀。同一资产改名时保留别名映射；不同实体不得因名称相近共用 ID。

### 人物提取记录如何登记

提取脚本的 `id` 是兼容旧消费者的单份结果内序号；`extraction_id` 带本次 `extraction_run_id`，用于区分不同文件或运行的提取记录，不能证明人物身份。字段定义见 [人物 JSON](json-schema.md)。

- 未登记的提取结果保持 `asset_id: null`。核对源证据与已有登记后，复用已确认的稳定 `asset_id`，或为新实体建立 ID；不凭姓名、序号或文件名自动匹配。
- 登记表用 `source_extraction_ids` 保存映射到该资产的提取记录；同名异人分别登记，异名同人经证据确认后可映射到同一资产。
- 重新提取会生成新运行标识，需重新核对映射；保存过的同一结果内标识不变，不因重新排序或改显示名而重编。
- 旧数据没有 `extraction_id` 时，先为每份来源结果分配唯一 `extraction_run_id`，再将 `运行标识:旧id` 作为来源键；同名文件与多份内联输入也各自分配。旧项目已确认的稳定 ID 原样继承，不能批量重编号；仅有旧序号而无身份依据时保留未登记状态。

## 二、状态

每个资产只取一个当前可用状态：

1. `identified`：已从源材料识别，尚未完成设计。
2. `designed`：资产卡已确认，尚未生成或制作文件。
3. `candidate`：已有候选文件，尚未验收。
4. `approved`：已验收，可供下游使用。
5. `uploaded`：已进入目标生成入口，并记录真实附件/引用编号。
6. `deprecated`：停止新增使用，保留旧项目追溯。

只有 `approved` 或 `uploaded` 可以被正式导演稿当作真实资产引用：`approved` 必须记录真实文件，`uploaded` 必须记录目标入口的 `target_reference`。进入视频生成提示词的资产必须为 `uploaded`。提示词本身不是资产文件。制作状态不代表权利状态；外部或用户素材另按 [来源、许可与使用边界登记](source-and-rights.md) 记录 `rights_status` 与用途限制。

## 三、版本与变体

- 身份不变、只发生普通动作时复用同一身份资产，动作写在分镜中。
- 换装、明显伤情、破损、湿透、开合、变形或时间阶段会持续影响后续镜头时，建立状态变体。
- 版本修订不得覆盖已经被分镜引用的旧版本；新版本登记变更原因与影响范围。
- 临时资产明确标注，不得冒充正式版本。

## 四、文件与引用映射

每个实际文件记录：绝对/项目相对路径、格式、版本、用途、验收状态和目标入口引用。导演稿可以使用 `@资产名` 便于阅读；生成块必须映射到用户界面真实可用的附件编号或引用方式。

参考缺失时写“待制作/待上传”，不能假装绑定。参考图只证明外观或结构，不等于动作已经生成成功。

## 五、跨类别关系

- 人物—服装：谁在什么场次穿哪一版本。
- 人物—道具：初始持有、转移、损坏和最终归属。
- 场景—道具：固定陈设、可移动物件和世界坐标。
- 场景—光源：固定光源位置、开关状态和时间变化。
- 场景—观察方向：同一地点各 View 所属的时间/天气状态，以及同组 View 共用的主光来源；改光时同组板一并更新。
- 场景—状态：已使用的场景状态及其可见证据，和后一状态对前一状态痕迹的继承。
- 资产—分镜：哪些镜头需要该资产的角度、状态或引用。

世界位置不能因摄影机左右变化而漂移。场景参考只覆盖一个方向时，不虚构不可见的关键布局；必要时补角度、白模或修改机位。

## 六、交接包

按 [资产输出契约](asset-output-schema.md) 交付项目与场次来源、完整登记项及交接投影；不要将记录压缩成只有显示用 `ref`。结合下游实际镜头说明已支持的角度和状态、缺口、未确认设计与依赖限制。交接可用性按本档“状态”规则判定。

分镜新增资产需求时回写到登记表；资产补齐后再更新引用，不在分镜正文中另建一套资产命名。

## 七、检查

- [ ] 同一实体没有重复 ID，不同实体没有共用 ID
- [ ] 原文事实、推断、设计补全和未知已分层
- [ ] 版本、状态变体和弃用关系可追溯
- [ ] 文件真实存在，候选、批准和上传状态未混淆
- [ ] 下游镜头所需角度和状态有覆盖或明确缺口
- [ ] 场景已登记控制点、动线、受保护锚点与已用状态；同组 View 的光线来源一致
- [ ] 生成提示词没有把待制作项写成已绑定引用
- [ ] 剧本版本和场次 ID 与当前源稿一致，旧版本资产已标明影响范围
- [ ] 外部素材的来源和使用边界有记录；制作准入与权利确认未混写
