# 资产提示词

只在用户点名资产，或当前制作确实需要资产时使用。需要模型适配提示词时，图像引擎未指定即用默认 **GPT Image 2** 并记录，不为此单独追问；用户指定其它引擎时按其规格生成。未核验的引擎不输出“可直接生成”的版本。

目标引擎从 [18-image-engines.md](18-image-engines.md) 的可选清单中确认；引擎不同会改变提示词结构、负面词写法和参考图分工。未核验的引擎不写“已适配”。

## 建立锚点

从剧本和已确认设定提取稳定外观：

- 人物：身份、面部与发型、体态、服装结构、辨识特征。
- 场景：空间结构、出入口、固定陈设、材质、主要光源。
- 道具：轮廓、尺寸、材质、结构、文字和状态。

同一资产使用稳定 ID，并区分源事实与设计补全。命名保持清楚可引用，不强制特定语言或示例品牌。

### 补全的边界

信息缺省时只补到画面成立为止：写清身份或品类，加上完成画面所需的姿态、外形、材质与光影，不发明用户的设定。

- 「独行者」→「一名穿着御寒服装的独行者」。
- 「香水」→「一瓶造型精致的透明玻璃香水瓶」。

角色数量、随身物件、职业装备、品牌状态、文字状态、核心道具、IP 元素和叙事事件以用户原话为唯一来源，未提及就不写入。

### 场景提示词的尺度链

场景不要写成景物名词清单。按“从世界到人”的尺度组织，未参与画面或剧情的层级可以省略：

1. **场景身份与世界规则**：地点是什么、处于地面/山体/云海/室内何处，以及最关键的现实或幻想规则。
2. **总体空间结构**：主轴、街道、广场、院落、平台、桥、出入口及高低关系；先保证人能在其中行动。
3. **主地标与材质**：只锁定最能识别地点的建筑或自然地标，并写明材料、表面、连接方式及老化/洁净程度。
4. **人尺度活动**：人物数量级、身份、服装轮廓、正在进行的具体活动及其与空间的关系，用来说明场景功能和比例。
5. **辅助环境元素**：植物、水体、灯具、鸟兽、雾尘等只选能建立纵深、方向或叙事的部分，不把候选词全部塞入。
6. **视角、光线与空气**：摄影机从哪里看，主体落在哪一层，主要光源、暗部可读性和雾/云/尘的空间作用是什么。

文化地名、神话专名或世界观名词应保留，同时补充可见翻译。比如专名表达“这是哪里”，建筑材质、城市结构和人物活动表达“它看起来怎样”；不能假定模型只凭专名就知道项目设定。

判断场景是否成立，优先看：建筑关系能否连接、道路与桥是否有落点、人物是否有可行路径、瀑布/水体是否有来源与去向、光源是否与空气介质一致。生成引擎容易出现的空中断桥、无支撑楼阁、无源瀑布和重复门洞，需要通过空间关系约束，而不是增加 `highly detailed`。

### 场景锚点块（交接给图像或视频模型）

场景进入下游时，用一段可复用的锚点块固定地理，而不是每次重述整个场景：

```text
[@场景标签]，[空间类型与布局]，[固定锚点]，[演员活动区]，[叙事物件]，[光源与方向]，[色彩与材质规则]。
保持一致：[3–5 个锚点]。
避免：[禁止漂移]。
```

多镜同场景时，在改变镜头语言前重复 `@场景标签`、固定锚点与活动区。竖屏项目把「演员活动区」写成 9:16 动线五项（前景压迫物／中央通道／背景锚点／门槛轴／交接区），规则见 [场景一致性与状态阶梯](26-scene-consistency.md)。

**锚点数量控制在 3–5 个**。锚点多到模型无法同时保住时，实际结果是每个都保住一半。地理位置必须用世界坐标与相对关系表述（"窗边长桌的门侧"），不用随镜头变化的"画面左边"。

**元素多不等于稳**。场景越复杂，跨镜、跨集、跨 View 需要同时维持的东西越多，漂移概率按元素数量叠加。简化时按此顺序删：装饰性陈设、背景小物、纹理细节先删；**窗户位置、光线方向、地面质感三项不许删**——它们决定光源依据、亮暗结构与痕迹载体。可以少物件，不能少材质与光向的描述精度。取舍规则与俯视位置图见 [场景一致性与状态阶梯](26-scene-consistency.md)。

## 项目风格骨架：冻结段与变量段

多集、多场景、多资产的批量项目先定骨架，再逐张填变量，不每张重述一遍风格。

- **冻结段（项目级不变量）**：风格与材质锚点、光位与色温倾向、调色与影调、画幅与引擎参数。一次拍板后在同批资产中逐字复用，登记在 `meta.style_skeleton` 与 `meta.style_version`。调色与色彩配比可查 `zion-storyboard` 的色彩分级档；未安装时沿用已确认项目光色，或以自然语言描述当前资产所需的可见效果，不声称已经调用该档；风格槽只放 1 个锚点 + 1–2 个支撑 token。
- **变量段**：主体身份与数量、动作状态、空间与时间、前景元素、情绪基调、构图与主体占比、视角。

规则：

1. **独立投喂块自足**：需要单独提交的提示词逐字带上冻结段，不用“同上风格”。共享上下文的工作表可以引用已登记的冻结段；导出独立投喂块时再展开。
2. **冻结段只装风格层**：构图、景别、机位高度、主体占比、视角属于逐镜变量，不得写进冻结段；写进去会把全批锁成同一种景别。
3. **改冻结段等于换档**：替换光源、材质锚点或调色时按新档重新拍板，登记新版本（如 `style_v2`），不改动已交付资产。
4. **单张迭代只改变量段**：冻结段与同批其它资产不一致时，先查明是笔误还是有意换档，不默认后者。
5. **批量自检**：同批资产逐张比对冻结段文字，不一致的列出来源与版本；此项可先机器扫描，再由人工确认换档是否有意。

### 风格强度档

风格与内容谁主导，用三档控制，未指定时取 `S2`：

| 档 | 表现 | 用法 |
|---|---|---|
| `S1` | 只留轻微倾向，内容与写实基线为主 | 题材吻合但不想被风格压住 |
| `S2` | 风格清晰可见，仍不压过主体与事件 | 默认档 |
| `S3` | 风格成为主要视觉表现 | 风格本身就是卖点 |

- 强度只调节既有锚点与成像层的分量，不引入新的形容词。
- 冻结段里的题材锚点、胶片与印片层适用同一档强度；确需分档时写明哪部分强、哪部分弱。
- 成像层（胶片与印片）的词表见 [胶片与印片风格层](film-and-print-stocks.md)。

### 画面分层：前景 / 中景 / 远景

| 层 | 职责 | 必须写清 | 失败写法 |
|---|---|---|---|
| 前景 | 框景、遮挡、纵深、引导视线 | 一个具体物体及其材质或虚化程度 | “画面层次丰富”“有趣的前景” |
| 中景 | 主体与主体动作 | 身份、数量、动作状态及与空间的关系 | 主体缺席，或只写“人群” |
| 远景 | 环境身份与方向 | 地貌或建筑类型、主地标、地平线 | 把候选地标全部塞入 |

- 前景元素必须能被画出来：风化木栅栏、虚化高草、朝镜头涌来的尘云、皮革马鞍。
- 三层不要求填满，只在能建立纵深、方向或框景时使用。
- 尺度链决定“写哪几层信息”，分层决定“每个元素落在哪一层”，两者配合使用。

### 按用途选择动作

- 身份参考图优先让面部、服装结构和材质清楚可读，姿态服从所需视图。
- 海报、关键帧和动作资产可以表现冲刺、跃起或击中瞬间。写清姿态、重心、受力关系和接触位置，检查这些动作是否遮挡当前必须辨认的特征。
- 同一张静帧只呈现选定瞬间；需要连续过程时拆成关键帧需求，或交由视频分镜处理。
- 不用动作词黑名单替代对具体画面和用途的判断。

### 情绪基调与同族变体

- **情绪基调**：变量段给 1–2 个基调词，且必须与本张的事件、光位和题材档同向。基调与画面事件冲突时（基调写紧张对峙，画面却是黄昏里的安静漫步），改基调或改画面，不并排写进去。基调槽不替代具体的光位、材质与动作描述。
- **同族变体**：同类角色或同批场景需要多个变体时，先写基础短语，再叠加 1 个限定词（年龄、体态、磨损程度、天气）产生差异；不重写整句，也不改动已锁定的主角色锚点。

## 选择视图

人物、场景和道具的视图从分镜实际需要倒推。基准图优先清楚展示身份、比例和材质；正面、侧面、背面、局部、内部或状态变体只在会被使用时增加。人物设定表的排列、角度、水平线与同图/分图取舍按 [人物参考表模板](reference-sheet-templates.md) 和下游镜头需要确定。

背景与光线以易读、不污染身份为原则，按目标模型选择。场景资产可以是空镜，也可以在空间功能依赖人群时包含代表性人物。

## 写提示词

提示词包含资产用途、视角与构图、稳定锚点、材质与颜色、需要锁定的文字或结构、画质及目标模型支持的约束。

场景提示词推荐顺序：`场景身份与世界规则 → 总体空间结构 → 主地标/材质 → 人物活动与尺度 → 必要辅助元素 → 视角/构图 → 光线/空气 → 风格与引擎参数`。这是信息优先级，不是必须逐栏填满的固定模板。

删除同义质量词和复制残留：`highly detailed`、`ultra detailed`、`cinematic composition`、`8K`、`masterpiece`、`epic`、`stunning` 等不能替代具体结构、材质和光线；同一含义保留一次即可。堆叠这类词换来的是塑料广告片式质感，不是细节。移除 `&#x20;`、HTML 实体、网页换行标记和不可见尾随字符。风格形容词控制在能区分方案的少量锚点，不用 `elegant / majestic / dreamy / ethereal / surreal` 连续堆叠。

品牌、logo 和精确文字只照录用户或项目材料，不自行创造品牌规则。负面提示词是否使用、如何书写，由目标模型能力决定。画面内是否渲染中文、还是留空待后期合成，按目标引擎的文字通道口径决定，见 [图像引擎](18-image-engines.md)。

### 排他性需求写成正向结果

不要靠否定词描述“没有的东西”。把排他需求转成画面里实际成立的正向结果：

| 需求 | 转写 |
|---|---|
| 不要出现别的人 | 画面仅呈现该主体与所处环境，保持空间清空 |
| 背景别太乱 | 背景保持纯净，仅保留建立地点的必要元素 |
| 别和背景混在一起 | 主体独立置于前景，与背景形成清晰分离 |
| 不要出现文字 | 画面内无可读文字与标识，表面保持干净 |

### 需要先确认的画面冲突

两个核心要求在同一张静帧上无法同时成立时，先问一个决定性问题，确认后再出成品，不硬凑：

- 面部特写 **且** 完整展示全身。
- 纯俯视 **且** 完整呈现正面五官。
- 主体充满画面 **且** 保留大面积标题负空间。
- 逆光剪影 **且** 面部细节清晰可读。
- 静态立姿 **且** 表现大幅位移或冲刺中的动作。

### 输出形态

- 默认按信息优先级连续成文（场景提示词顺序见上）。
- 用户要“一条可直接复制的提示词”时，用短标签分模块、分号连成一条：

```text
【画面类型】…；【景别与机位】…；【构图】…；【主体】…；【动作与表情】…；
【空间调度】…；【环境层次】…；【光影与色彩】…；【美学与材质】…；【画幅与质量】…
```

- 标签只是分栏记号，不替代具体描述；模块内容不足时合并，不为了凑齐标签填同义词。
- 画幅、文字通道与引擎参数按已确认引擎填写，不写“模型无关”的通用版。

## 用途与版式声明

资产图如果还要当版式素材用（PPT 背景、海报底图、Banner、封面、缩略图、商品主图），必须在提示词里声明用途与版式。不声明，模型会把主体摆满画面，后期无处放字。

声明四件事：

1. **用途**：这张图之后要被怎么用（底图 / 主视觉 / 缩略图）。
2. **主体占比**：主体占画面多少（小占比 / 半幅 / 满幅）。
3. **主体位置**：左 / 右 / 中 / 下三分之一。
4. **负空间**：哪一侧留空、留多大、留给什么（标题区 / 按钮区 / 字幕区）。

示例：`主体占画面约四分之一，位于右侧；左侧大面积负空间留给标题；横版构图`。

- 版式素材与身份参考图分开做：参考图要中性背景、主体填满；版式素材要留白。
- 需要的画面内文字按 [文字通道口径](18-image-engines.md) 决定渲染还是后期合成；负空间大小以目标文字量为准。
- 画幅与安全区按投放渠道定，不沿用生成工具的默认比例。

资产生成后登记实际文件和版本。分镜只能引用真实存在的资产；参考已经锁定外观时，视频提示词主要写当前变化，是否重述身份按目标模型方法决定。
