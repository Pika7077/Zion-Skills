# Zion Assets：资产设计与管理

负责“画面中有什么、长什么样、如何稳定复用”。统一管理人物、场景、道具、服装/状态变体、动物/生物、载具、图形文字、特效元素以及按需的声音身份参考。正式镜头调度、时间线和视频生成提示词由 `zion-storyboard` 负责。

## Zion 家族统一规则

冲突优先级：用户明确要求 > 源剧本/文档/视频证据 > 已确认项目设定 > 已批准的粗分镜资产需求 > 下游制作需要 > 已核验图像模型能力 > 模板与经验。

资产事实分为四层：

- **原文明确**：文本、对白、画面或项目 brief 直接支持。
- **合理推断**：有独立证据支持，并说明依据。
- **设计补全**：为了制作提出的可替换方案，不冒充原作事实。
- **未知**：材料不足，保留占位，不强行补齐。

资产只负责稳定身份、结构、材质、状态和可引用文件，不决定剧情、不拆正式镜头，也不把待制作资产写成已上传或已绑定。

## 资产模式

| 模式 | 处理内容 | 典型交付 |
|---|---|---|
| 人物 | 姓名/别名、身份、外貌、体态、服装、关系、状态变体、音色身份 | 人物卡、关系表、JSON、参考视图与提示词 |
| 场景 | 空间拓扑、出入口、固定锚点、材质、光源、时间/天气状态、场景状态阶梯 | 场景卡、空间关系、所需参考角度与提示词 |
| 道具 | 轮廓、尺寸、结构、材质、功能、文字、归属、变化状态 | 道具卡、状态变体、比例/细节参考与提示词 |
| 其他 | 服装独立款、生物、载具、武器、特效元素、图形文字、声音身份等 | 对应资产卡、版本与引用说明 |
| 资产包 | 多类资产统一编号、版本、文件和相互关系 | 资产登记表、缺口清单、制作顺序与交接包 |

只读取当前任务需要的模式，不强制每次生成全套资产。

## 需求与默认值

先使用已提供的材料与既有授权。只追问会改变交付范围、源事实或关键制作选择的缺口；关联问题可合并询问，其余可逆选择说明合理默认后继续。按任务需要核对：

1. 输入来源及版本：剧本、文档、视频、粗分镜或已有资产。
2. 资产范围：人物、场景、道具、其他或组合。
3. 交付范围：只提取、资产卡、JSON、提示词、参考图需求、已有文件登记或完整交接包。
4. 对源材料的处理：只提取、允许合理推断，或允许设计补全。
5. 下游用途：剧本开发、粗分镜验证、正式分镜、图像生成、视频参考或宣传版式。
6. 视觉风格、画幅/版式、所需角度和不可修改项。
7. 需要图像提示词时的目标模型、版本/入口和已有参考图。

关键选择无法从上下文判断时给简短选项与建议，等待该项答复，同时推进无依赖工作；已有授权无需特定口令重申。纯提取和登记不询问图像模型。需要图像提示词时，从 [图像引擎](references/18-image-engines.md) 读取并记录当前默认选择；默认采用不等于已生成或已验证。

## 承接与让渡

- 故事、场次、对白、人物动机和结局：`zion-script`。
- 人物、场景、道具和其他资产的提取、设计、提示词、ID、版本与登记：本档。
- 粗分镜提出的资产需求可由本档承接；正式导演分镜、镜头时间线和视频提示词：`zion-storyboard`。
- 剧本、资产、分镜、提示词或生成结果的独立验收：`zion-qa`。

相关技能未安装或不可读时，完成本技能范围内的交付并标出后续需求；不声称已经调用其它技能，不因可选参考缺失中断资产工作。

制作流程允许迭代：剧本锁定 → 粗分镜提出角度/状态需求 → 本档补齐资产 → 正式分镜挂载真实资产。粗分镜不是本档职责，但可以作为资产需求输入。

## 工作流程

### 1. 提取源事实

读取材料，提取可复用实体、别名、关系、外观、空间、功能、状态和证据。人物识别与合并见 [人物提取规则](references/character-extraction-rules.md)；脚本只生成骨架，语义仍需人工复核。

### 2. 建立需求清单

从剧本和粗分镜倒推真正需要的身份、观察角度和状态。参考角度覆盖实际镜头即可，不强制人物三/四视图、场景五视图或道具全状态。规则见 [资产一致性](references/14-asset-consistency.md)。

### 3. 建立资产登记

继承剧本的项目与场次标识，给每个资产稳定 ID；人物提取序号须先按证据映射，不能直接充当稳定身份。登记、版本和可用状态见 [资产登记与交接](references/asset-registry-and-handoff.md)；需要结构化交付时读取 [资产输出契约](references/asset-output-schema.md)。

### 4. 分类型设计

- 人物参考表和身份差异：读取 [人物参考表模板](references/reference-sheet-templates.md)。
- 场景、道具及其他资产提示词：读取 [资产提示词](references/asset-prompt-builder.md)；要做一图多景的拼图时，先按该档的多格拼图一节判断是方向预览还是成品资产。
- 生物、载具、武器、图形文字、特效或声音身份需要专门设计与交接时：读取 [其他资产设计](references/other-asset-design.md)。
- 场景一致性维护（竖屏动线、净空与体量、场景状态阶梯、跨 View 光线对齐、环境叙事、视频可用性预检）：读取 [场景一致性与状态阶梯](references/26-scene-consistency.md)。
- 批量项目先定 [项目风格骨架](references/asset-prompt-builder.md#项目风格骨架冻结段与变量段)（冻结段 + 变量段），再按该档的批次规划出图：**先出基准图，达标后再派生变体**，基准不达标不派生。
- 系列剧或多项目共用资产（同一实体跨项目、风格锚点继承）时，读 [资产登记与交接](references/asset-registry-and-handoff.md) 的系列与跨项目复用一节：ID 沿用、状态变体不照搬、证据层在新项目里重判、锚点冲突以已冻结的风格骨架为准。
- 题材视觉锚点：读取 [题材风格预设](references/19-genre-style-profiles.md)，只取与当前资产有关的少量锚点。
- 用户用影人姓名、影片名或俗称描述风格时：读取 [导演与摄影师视觉语言拆解](references/director-vision-language.md)，默认稳定模式，成品不出现人名。
- 需要胶片感、电影感或影院拷贝质感时：读取 [胶片与印片风格层](references/film-and-print-stocks.md)，把成像层纳入冻结段同批复用。
- 外部参考、字体、音乐、声音、人物形象、品牌或用户上传素材会进入制作或交付时：读取 [来源与使用边界](references/source-and-rights.md)，登记证据与待确认项，不把制作准入当成权利确认。

人物、场景与道具之间共享项目世界规则，但各自保留独立 ID 和版本。服装若只属于单个人物的稳定外观，可作为人物字段；需要换装、复用或独立版本时登记为资产。

### 5. 适配图像引擎

需要图像提示词时读取 [图像引擎](references/18-image-engines.md)。未收录、未经核验的引擎不输出“已适配”版本。文字、负面参数、参考图和版本参数按已确认引擎处理。

### 6. 交接

交付时区分：

- 已存在且可引用的文件。
- 已生成但尚未验收的候选资产。
- 只有提示词、尚未生成的待制作资产。
- 因材料不足暂时未知的字段。

未制作或未绑定的资产进入缺口清单，不冒充真实引用。交接保留稳定身份、版本与可用性证据；具体准入和版本规则见 [资产登记与交接](references/asset-registry-and-handoff.md)，结构化投影见 [资产输出契约](references/asset-output-schema.md)。

## 输入处理与脚本

人物模式可处理 TXT、DOCX、PDF 或可解析视频。视频结论优先结合语音、关键帧和元数据；证据不可用时说明限制。

```text
python scripts/parse_input.py <file>
python scripts/extract_characters.py <text-file> --source-type 剧本
```

批量任务逐文件保留来源，以 `extraction_id` 区分提取记录，合并前核对同名异人和异名同人；旧 `id` 只在单份结果内有效。脚本不登记稳定 `asset_id`，也不会自动完成关系推断、设计补全或视觉定稿。

## 输出契约

| 请求 | 默认交付 |
|---|---|
| 人物提取 | 人物总览 + 结构化人物卡；需要机器读取时附 JSON |
| 场景/道具提取 | 资产清单 + 结构/材质/状态卡 + 缺失信息 |
| 单类资产提示词 | 资产卡 + 所需视图/状态 + 目标引擎提示词 + 待确认项 |
| 完整资产包 | 统一登记表 + 分类资产卡 + 真实文件映射 + 缺口与交接说明 |
| 批量处理 | 单文件结果 + 合并映射 + 冲突/失败清单 |

人物专用字段见 [人物输出 Schema](references/character-output-schema.md)；通用资产字段见 [资产输出契约](references/asset-output-schema.md)。

## 质量标准

- 可识别资产无明显遗漏，别名和同一实体正确合并。
- 原文事实、推断、设计补全和未知清楚分开。
- 人物、场景、道具和其他资产的 ID、版本与状态不冲突。
- 参考角度和状态覆盖实际用途，不为凑模板增加无用视图。
- 如实保留源材料的相似或同貌设定；授权设计时建立满足实际镜头识别需要的稳定锚点。
- 场景几何、出入口和关键路线能支持计划机位。
- 需要表达压迫、被困或落差时，场景的**净空与体量**（头顶净空、身体余量、可退距离、比例参照）已登记，不只写动线。
- 不露脸镜头多的角色写明**步态与行走特征**；背影或远景里仍能被认出。
- 场景有可指认的控制点与动线，不是只有氛围的空房间；用过的场景状态有可见证据且能继承。
- 同一地点同一时间/天气状态下，各观察方向的主光、色温与光比方向已对齐。
- 只引用真实文件，不把提示词或待制作项冒充已可用资产。
- 长尾资产的可动结构、功能、状态与下游用途足以复现；图形文字、特效层和声音身份使用各自需要的专用字段，不只塞进通用描述。
- 外部素材的来源、已知许可状态和使用边界可追溯；制作状态与权利状态分开判断。
- 模型特定技巧只在目标模型适用且已确认时启用。
