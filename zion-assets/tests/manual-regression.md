# zion-assets · 人工回归

1. 剧本人物提取覆盖主角、配角和有叙事作用的匿名人物；别名合并须有证据，同名不自动视为同人。
2. 视频结合可用 ASR 与关键帧；证据缺失明确说明，不把元数据冒充人物证据。
3. 区分原文事实、推断、设计与未知；原文的常见形容词可保留，不为了去模板化改写事实。
4. 双胞胎、统一制服、刻意同貌设定照实保留；仅在授权设计且用途需要时提出差异，不凑两项或三项配额。
5. 年龄可保留在人物卡；按目标模型选择表达，不设全局禁词。
6. 参考表背景、视图和光线服从可读性；只需正脸时不补全套视图，不默认同一种体型。
7. JSON 请求符合 schema；普通人物分析无需强制附 JSON。
8. 批处理单文件失败记录后继续；同名文件、内联输入的不同运行获得不同 extraction_run_id / extraction_id。
9. 旧 id 只在单份提取结果内有效；按出现次数重新排序不能改动已登记的稳定 asset_id。
10. 新提取结果 asset_id 为 null；确认身份后通过 source_extraction_ids 登记映射。旧结果须补来源键后再合并，不能用 char_001 覆盖另一批记录。
11. 同一提取器连续处理两份材料不得累积上一份人物。
12. 人物、场景、道具可成套处理；只要单类资产时不强制制作其它类型。
13. 完整包采用统一登记表；正式分镜需求交给 zion-storyboard，不能声称资产制作已完成导演工作。
14. 新角度或状态需求新增需求或版本，不偷偷修改已批准身份。
15. 未生成、未验收、未上传的状态须如实区分；正式导演稿和生成投喂分别满足登记档的准入规则。
16. 纯提取不询问图像模型；要图像提示词而未指定时记录默认 GPT Image 2，不主动引入 Midjourney。
17. 已有制作授权足以覆盖常规可逆选择，不要求“按你推荐”等口令；真正影响源事实或关键方向的缺口才追问。
18. 批量项目区分冻结段与变量段；独立投喂块完整展开冻结段，共享工作表可引用其登记位置。
19. 冻结段差异先查笔误或版本切换；有意换档登记新版本，不覆盖已交付资产。
20. 交接保留 asset_id、version、status、files、target_reference，不缩成一个显示名。
21. 动作海报或关键帧可以冲刺、跃起、击中；检查选定瞬间的姿态与受力，不以动作词判失败。
22. 身份参考图若动作遮脸或遮挡服装结构，按实际用途提出调整，不外推为所有静帧禁令。
23. GPT Image 2 透明背景按预览能力与实际入口核验；不沿用“不支持”结论，不承诺身份绝对锁定或固定文字准确率。
24. Midjourney 参数随用户实际版本核验；不混用 V7 主体参考与 V8 编辑机制。
25. 仅安装本技能时仍能完成资产卡和提示词草案；其它技能的色彩词库等不可用时采用项目光色与自然语言，不声称已调用。
26. **有意融合与无意混用**：“古风人物站在赛博都市前，水墨叠霓虹。”识别为**有意融合**，建立主从结构（古风为主承担形制与身份，赛博为从只提供光色与局部元素），补接缝锚点与分区色板；不按“不混两个美术体系”直接判违例，也不等量并置两套体系。
27. **融合换风格只动两块**：“这套视觉换个主体和场景。”沿用 [题材风格预设](../references/19-genre-style-profiles.md) 的结构分离写法：只替换主体词块（朝代形制 + 服装材质主色 + 单个从体系元素）与场景词块（传统介质 + 未来媒介），保留接缝、质感与色调词块；不重写整段。
28. **场景不是背景**：“设计一个总裁办公室。”先答五个场景闸门问题——谁控制入口与座位、谁被挡住、哪个物件能被递出或签署、9:16 前 3 秒能读出什么、下一镜继承什么；给出具体权力机制与可动工作面，不交一个漂亮的空房间。
29. **竖屏动线**：同一场景用于竖屏短剧时，写清前景压迫物、中央通道、背景权力锚点、门槛轴与交接区五项；不把横构图宽厅直接当竖屏可用空间。
30. **场景状态有证据且能继承**：“上一集在会议室撕了合同，这一集还是同一间会议室。”不干净复位：沿用 S 状态登记，保留散落纸页、椅子位置、灯光状态等痕迹；受保护锚点（门轴、窗墙、桌的朝向）不变，只改变允许变化项。
31. **跨 View 光线对齐**：同一走廊做了朝北与朝东两块参考板，会被同一场戏的正反打剪接。两块必须共享同一主光来源、色温关系与光比方向；差异只能是朝向造成的逆光关系和局部落影，并写清来源。各板单看都成立、拼起来像两个房间的，判为问题。
32. **改光走状态差异**：“同一场景要加一个夜雨版本。”作为新的时间／天气状态登记，并交代该地点**所有**已有 View 如何变化，不只改被用到的那一块。
33. **空场政策**：场景空镜默认 `required`，不出现剧情角色与叙事动作；确需尺度参照时用无身份中性物（刻度底座、手掌比例、已知功能结构），不引入剧中人物，也不静默改政策。
34. **叙事物件数量与来源**：一场戏用 1–2 个可画出来的叙事物件（未吃完的饭＝匆忙离开），磨损符合使用逻辑（门把手、桌沿先磨损）；不把五层环境叙事全部塞进一张图，也不写“有氛围感的小物”这类无法画出的描述。
35. **场景锚点 3–5 个**：交接锚点块给 3–5 个锚点并写明保持一致项；位置用世界坐标与相对关系（“窗边长桌的门侧”），不用随镜头变化的“画面左边”。
36. **视频可用性预检**：核心场景做 5–10 秒运动试镜（进入停在中央通道、穿过房间、门槛阻挡、物件在交接区移动、摄影机推进、两人对峙、下一镜继承痕迹），再贴 `scene_video_ready` 或待修标签；不把静态参考图直接声称可生成视频。
37. **取舍顺序与三项核心质感**：“这个地牢场景元素太多，老是画不一致。”按取舍顺序过筛——先删装饰性陈设、背景小物、纹理细节，保留叙事物件 1–2 个；**窗户位置、光线方向、地面质感三项不许删**，写入 `core_textures`。不为了“简化”把材质与光向的描述精度一起砍掉。
38. **俯视空间位置图**：“两条走廊加一个拐角，两块参考板对不上。”空间有两个以上入口、有拐角隔断或有遮挡关系时补俯视位置图，标出入口与开门方向、窗与主光来源、中央通道与前景压迫物、交接区、各 View 观察位、可站区与不可通行区；单一开间正面拍摄的小场景可省。位置图是内部核对工具，不进画面、不出提示词。
39. **完整空间设定驱动下游**：“把这段空间设定丢给模型自动拆分镜。”先确认空间事实已写全（`fixed_anchors` 相对关系、`view_set` 观察位、`light_source_shared` 主光与色温、`state_ladder` 可见证据）；未记录的空间事实不会被下游补上，只会被自由发挥。镜头顺序、时长与切点归 `zion-storyboard`，本技能不定义。
40. **生物结构与动作能力分开**：“做一只会飞的六足兽。”先登记肢体、关节、支撑点、尺度与稳定轮廓，再记录飞行时哪些结构保持不变；不因像鸟就自行补入鸟类骨骼和速度。
41. **载具拓扑可用**：“给未来摩托做一张帅图。”若下游有人物上车和转弯镜头，需补驾驶位、入口、可动结构、人物尺度与活动范围；单张侧面气氛图不能冒充功能参考。
42. **武器资产不代写剧情动作**：记录握持区、操作件、作用端和状态变体，不编造使用教学或伤害结果；具体动作与反馈交给分镜。
43. **准确文字与视觉身份分层**：“合同封面要精确写公司名。”版式、材质与色彩进视觉身份，逐字文本进准确内容字段；需要可靠成品时保留后期可编辑路径，不只依赖生成图中文字。
44. **特效有生命周期**：“加一团高级魔法。”不合格；应写发生源、范围、方向、发展、交互光、遮挡关系、结束与残留，并按需要登记前后景层、遮罩或透明通道。
45. **声音身份不是台词样本**：登记音域、质感、语速、重音和跨情绪稳定锚点；具体台词与当前情绪不写成身份。没有真实文件时不能标为 approved 声音资产。
46. **来源未知不补猜**：网上找到的参考图没有可核实来源时，`source_provenance` 与 `rights_status` 标为 unknown，并列待确认；不能因为文件可下载就写“可商用”。
47. **用户声明与独立确认分开**：用户说“我有权使用”可记录 `user-asserted` 及声明来源，但不自动改成 `confirmed`。
48. **制作准入不等于权利确认**：图片已验收并上传可以是 `uploaded`，同时权利状态仍为 `pending`；交付报告同时呈现两条状态，不能互相覆盖。
49. **派生文件继承来源**：去背、裁切、调色和多语言替换后的文件保留父来源；替换来源后检查资产登记、分镜引用、提示词和交付包，不只改当前文件名。
50. **压迫性空间要登记净空与体量**：“这场在低矮的桥下修车，要压得人喘不过气。”除动线外，登记头顶净空（可站直／需低头／无法站直）、身体余量、可退距离与比例参照；只写通道不写净空，场景会失去压迫感。净空随状态变化（堆物、支架落下）时按场景状态阶梯登记，不另建场景。
51. **步态是可识别锚点**：“这个角色大部分镜头是背影和远景。”在不露脸镜头较多的角色卡里补 `visual_dna.gait`（步幅、落步轻重、重心、手臂与习惯动作），只写可见事实；不写步态时背影镜头无法辨认，也不要写成“气质沉稳”这类形容词。
52. **系列复用沿用同一 ID**：“第二季还用上一季那个人和那间办公室。”沿用同一 `asset_id` 并标注项目群；身份锚点、场景基线、冻结段可复用，状态变体、场景状态阶梯与 `before_after` 不跨项目照搬；复用件在新项目里的证据层按新项目的源材料重判，且必须落到新项目可见的真实文件。
53. **锚点冲突以冻结段为准**：“这一季想把主光换成暖调。”先看该项目已冻结的风格骨架；要改锚点就走冻结段版本升级并登记影响范围，不在单个项目里静默改一处，也不让两套风格留在同一项目里。
54. **重制触发先判类型**：“服装换了阶段，旧图还能用吗？”按重制触发清单判断是新建状态变体还是必须重制；源稿修订、锚点或冻结段更换、换引擎、验收降级各对应不同处置，旧版本标 `deprecated` 并登记影响范围。只是换了机位角度或当前镜头用不到，不属于重制理由。
55. **批次规划：基准先行**：“这批十二张人物图一起出。”先出一张基准图，锚点、光线与冻结段符合设定后再派生角度、状态与同族变体；基准不达标先改基准或改冻结段，不批量重跑；跨冻结段的资产不放同一批，并记录每张图所属批次与依据的基准版本。
56. **多格拼图先判用途**：“把这四个场景做成一张四宫格。”先判用途：方向预览、情绪板可以拼；要用于分镜引用的成品资产必须**分别生成**——一图多格是一个文件装多个画面，无法登记单个 `asset_id`，也无法单独重制其中一格。
57. **格数与排列要写明**：“画一个四格拼图。”要写清几格、怎么排（如“2×2，自左至右、自上而下”），并用左上／右上／左下／右下把位置对应到内容；不写排列，模型会自己安排。
58. **拼图用冻结段＋变量段组织**：“四格每格都把风格、光线、色调复述一遍。”不合格；整体统一项写在头部作冻结段，每格只写差异作变量段。
59. **跨格同人不可控**：“四格都要出现同一个主角，而且要长得一样。”方向预览可接受每格略有差异；需要一致时改为分别生成，不靠一图多格实现。
60. **格内不要求精确文字与复杂调度**：“每格再加一句字幕和精细走位。”不合格；多格与文字叠加时失败率最高，格内也不写前中后景调度——预览图只需方向对。
61. **拼图不升级为成品**：“四宫格里挑一格直接用。”方向预览的拼图不能直接当成品资产，选定方向后按单图重出并登记；反向同理，已登记为资产的图不拿去当拼图用。
62. **图像类型声明要能排除真实错误方向**：开头写“电影剧照”可以留——它排除插画、游戏 CG 与海报观感；判据是**能否排除一个真实存在的错误方向**。只是想显得高级就删；“电影感”“大片质感”这类氛围形容词不属此列，按同义质量词的纪律处理。
63. **技术名词要换成表面事实**：“写 PBR 材质、真实流体模拟、8K。”这些描述制作方式或期望精度，不是画面上能看到的表面；改成磨损金属的高光走向、液体的黏稠度与飞溅形态、湿润沥青的反光与织物经纬。
64. **静帧不写听觉信息**：“写‘没有声音，没有动静’。”静帧承载不了声音，这类描述既无法呈现又占掉预算；要表达孤寂就写可见事实——空旷画面、无人、被拉长的影子、只有一处亮着的窗。
65. **负面参数不替代正向描述**：“想排除卡通感，加 `--no 卡通` 就行。”低关联瑕疵（水印、签名、多余文字）可用负面参数兜底；高关联概念仍要改写成正向描述（写实拍材质与真实比例），不能只靠否定处理。
66. **参数不拼接不同代际**：“同一条提示词里 `--v 8.2` 与 `--v 7.0` 混着写。”不合格；只使用当前版本与入口已核验的参数，不拼接不同代际，也不声称系统会自动回退；未核验的参数要标注来源与核验日期。
67. **类型声明与【画面类型】栏要一致**：“【画面类型】写电影剧照，正文却按插画质感描述。”两处必须同侧；声明排除的方向变了，正文描述要跟着变，否则声明落空。
68. **悬浮要有排列规律**：“画一堆碎石悬浮在空中。”无规律的悬浮读成生成失误；要给可描述的秩序（同心圆环、等距、沿一条线、向心汇聚），并给成因或参照（气流、气场、“沿她身体外侧排成两列上升”）。
69. **非物理元素不堆叠**：“一图里同时画漂浮的椅子、飘落的书页、无视重力的水。”违反物理的元素堆多了会互相稀释；至少让一种有清晰秩序，其余留小。
70. **悬浮的承担检验**：“这些悬浮物按什么规律排？”答不出来就会被读成错误；把它换成“被风吹起”后画面照样成立，说明悬浮没有承担设计意图。
71. **影人姓名只作检索入口**：“按韦斯·安德森的风格来。”读 [导演视觉语言](../references/director-vision-language.md) 的条目，取出构图与镜头、调度与空间、光色与材质三项特征并分派到提示词模块；成品不出现人名，也不写“某某风格”了事。
72. **锚点模式只点一次名**：“这次要保留导演名字。”在画面类型开头写“受〈姓名〉相关影像语言启发”，其后仍展开具体机制；姓名不替代构图、光位与材质的描述。
73. **形制不混搭**：“把对称复古舞台和中式仪式感各取一半。”条目之间不混搭互相矛盾的形制；按用户明确要求优先、其次题材档的口径取舍，不平均混合。
74. **未收录影人就地拆解**：“按一位本档没收录的导演来。”仍按构图与镜头、调度与空间、光色与材质三项就地拆解；不因未收录而拒绝，也不只回一句“某某风格”。
75. **影人姓名不改变主体**：“参考王家卫，但人物和事件按我的剧本。”影人姓名只决定视觉形式，主体、环境与事件继续以用户原始需求为准，不为贴合风格改剧情。
76. **跨条目组合要分工**：“既要巨构秩序，又要霓虹潮湿感。”两个条目可以并用，但**每个模块只由一个条目负责**——巨构管构图与调度（尺度对比、负空间、低地平线），霓虹管光色与材质（霓虹混合、深黑阴影、潮湿反光）；同一模块出现两套矛盾规则（两种几何秩序、两套色板）时只能留一套。
77. **组合后要能溯源**：“这版风格混了好几位导演。”把构图、调度、光色、材质四个模块分别写出来，每个模块都能说清来自哪一条；说不清就是无依据的拼贴。用户点名一部作品时，先判断它跨了哪几个条目，不只取名字最像的那一条。
78. **青春感要拆开写**：“写‘日系青春感’。”不堆“夏天／白衬衫／逆光／胶片颗粒”；按 [导演视觉语言](../references/director-vision-language.md) 的 D15 拆开——留白与主体偏置、风只作用在指定对象（发丝衣角在动而人物主体稳定）、人物用动作承担叙事（奔跑、回望、落后一步、低头阅读）、环境参与表达。
79. **过曝要指定区域**：“写‘柔和逆光’。”要写清时间、方向，以及**允许轻微过曝的是哪块区域**（轮廓与眩光可以溢出，面部留在中间调）；只写“柔和”等于什么都没说。
80. **手持感要落到参数**：“加一点手持感。”应拆成焦距、机位、拍摄距离、轻微动糊与对焦漂移；只写“手持”会让画面变成随机乱晃。
81. **固定旁观机位**：“拍一段日常。”按 [导演视觉语言](../references/director-vision-language.md) 的 D16 取景——机位固定不动、人物在画面内进出自如，像一篇被旁观的日记；多人时站位分散、留白充足，宁可背对或侧背也不正面摆拍（理由见 `zion-storyboard` 的镜头语言档）。
82. **框要来自环境**：“为了好看加个木框前景。”框应由环境本身构成（门、窗、廊柱）自然切开画面，不为构图硬加装饰；硬加的框只是装饰。
83. **色调随剧情变化**：“全片一套低饱和绿。”基底是低饱和绿与暖棕，但色调要随剧情走——涉及死亡偏冷灰、家庭生活回暖；换色调要有可见触发（见 `zion-storyboard` 的色彩与影调档）。
84. **大画幅有贴近侧**：“诺兰风格，写 IMAX 和史诗感。”大画幅不只有宏大一侧——贴近人物时，眼神、皮肤与细小停顿是重点，背景渐次失焦；只写 IMAX 与史诗感会丢掉人物心理，那正是这种拍法的要点。
85. **年代从材质取色**：“写‘复古年代感’。”从沙土、旧木、羊毛、褪色棉布里取色（矿物沙色、灰白、烟草棕、灰绿），让年代落在具体材质上，不靠堆滤镜造年代。
86. **人物戏换一条顺序**：“人物戏也从环境开头写。”主体是人、场景只是容器时改用「人物与处境 → 景别与机位 → 光源 → 材质与色彩 → 一个心理动作 → 禁止项」，人物与处境放最前；“一个心理动作”单列成项。
87. **留在画外的事不要写**：“要表现爆炸，但只想拍他举起的手和镜片反光。”要留在画外的事**不在提示词里写出来**——写了反而会被画进去；单色画面另要写清天空、皮肤与衣料的明度排序。
88. **巨构与自然是并置不是融合**：“画一座长在山里的巨型建筑。”几何体与自然环境是**并置与植入**关系——边界清楚、不融合；画面只留一个视觉中心，其余归入负空间。
89. **粗野主义是可写的材质**：“写‘未来感建筑’。”建筑走粗野主义一系——裸露混凝土与石材、无装饰、结构外露；只写“未来感”给不出材质与体量。
90. **守暗部也要写明保留层次**：“低照度风格，暗部全黑、不要照亮。”风格上可以压暗部，但**要写明暗部保留到哪一层**（眼神／面部结构／仅轮廓／完全剪影），并给出轮廓光的来源；需要读表情时给正面弱补光——不能同时要求完全剪影和清晰表情（判据见 `zion-storyboard` 的光影系统档）。
91. **轮廓光要有来源**：“在人物边缘加一道高光线。”边缘光必须来自画面里可指的光源（侧逆光、窗外光、实用光），不能凭空加；它属 D05 的低照度取向，是气质层不是特效。
92. **迪金斯风格要写出空间任务**：“迪金斯风格，场景简洁留白就行。”取 [导演视觉语言](../references/director-vision-language.md) 的 D06 时，空间结构要承担视线任务——门、走廊、开口既遮挡也指向观众还看不见的地方，在场陈设要么挡住视线、要么划分关系；只写“简洁几何、留白”会得到空而无所指的景。
93. **迪金斯风格不靠虚化背景**：“迪金斯风格，背景全部虚化成光斑。”保留中等景深——背景是可读的空间证据，只在确需压掉杂乱时才虚化；焦段与景深取值按 `zion-storyboard` 的摄影机与质感词库，不由本档定档位。
94. **芬奇式的光要各管一件事**：“芬奇风格，把光打暗一点。”取 [导演视觉语言](../references/director-vision-language.md) 的 D07 时，光不只是照亮——每束光要能说出它承担什么：荧光灯的冷绿建立制度感、屏幕冷光把人物从环境里隔离、钠灯与暖色实用光把危险留在空间深处；只会说“暗”读不到控制感（多光源的分工写法见 `zion-storyboard` 的光影系统档）。
95. **芬奇式的压迫来自空间不来自机位**：“芬奇风格，用手持晃动表现他内心的不安。”D07 的机位保持冷静——不靠晃动、推近或倾斜替人物表达情绪；压迫感由空间与位置给出，门窗与框把人物切进网格，重复的门窗走廊让他像被监视与支配。
96. **芬奇式的克制不是青橙大片**：“芬奇风格，压成标准青橙对比。”D07 的冷暖存在但不做成夸张的青橙对比，偏色藏在低照度里、靠材质本色与干净黑位读出层次；青橙是取向明确的风格化预设，与“偏色藏在低照度里”方向不同，取用时按项目取向择一。
97. **雷弗恩式的色彩暴力不套色义表**：“雷弗恩风格，红色代表危险、蓝色代表死亡。”高饱和人造色与霓虹主导可以照写，但**色彩的固定含义不能照搬**——本库不套色义表；取 [导演视觉语言](../references/director-vision-language.md) 的 D17 时要能说清的是“这束洋红从哪来、它把画面切成了什么”，颜色在本片里什么意思仍靠作品自己反复绑定（见 `zion-storyboard` 的色彩结构档）。
98. **雷弗恩式的自然光不参与照明**：“雷弗恩风格，白天外景也铺一层紫色霓虹。”D17 的光色由人造色源主导、自然光不参与照明；需要日景时要把色源写进场景（招牌、灯箱、玻璃反射、车灯），而不是给日景加一层紫——那会读成滤镜（见 `zion-storyboard` 的色彩与影调档）。
99. **库布里克的光有两侧**：“库布里克风格，全片都用均匀柔光。”取 [导演视觉语言](../references/director-vision-language.md) 的 D09 时，光并非只有“均匀冷静”一侧——另一侧是刺眼的白色顶光、极高明暗对比与大面积极简纯色块（纯白、鲜红），用于超现实与临床般的冷酷；两侧按段落择一，不混成一种气质。
100. **库布里克的空旷不等于宏大**：“库布里克风格，来一片大负空间。”两者都用尺度对比，但 D09 的空旷靠**整洁对称与规律图案**（读来像数据图表、令人窒息），D05 的留白靠自然尺度的粗粝对比（读来宏大）；两条气质相反，选错会让整段往反方向走。
101. **施奈德式的仰拍要能说出理由**：“施奈德风格，主角一律仰拍，看起来像神。”取 [导演视觉语言](../references/director-vision-language.md) 的 D18 时，绝对中心与极端低角度是它的取向，但**角度不是权力标签**——仰拍不自动等于神明或崇拜；要能说出这个位置把观众的处境变成了什么关系，说不出就只是换了个角度（判据见 `zion-storyboard` 的镜头语言档）。
102. **油画感靠可辨识的明暗结构，不靠形容词**：“施奈德风格，加 cinematic dark dramatic lighting。”不合格——那串是抽象词，要换成可执行的灯光条件（明暗对照、光源方向与来源、暗部保留到哪一层）；伦勃朗光只有在鼻影与背光侧面颊构成三角亮区时才成立，只写“半张脸暗”不算（见 `zion-storyboard` 的光影系统档）。
103. **大画幅也能扛在肩上**：“大画幅风格就得上摇臂。”D04 的构图与镜头里，大画幅不必架在摇臂上——把通常要上摇臂的重型机器扛在肩上，得到“极高清晰度 + 微微呼吸感”的反差；但要写清幅度与来源（呼吸、脚步、重心），不能只写“抖”（判据见 `zion-storyboard` 的摄影机与质感档）。
104. **点名摄影指导时不继承搭档的题材**：“霍伊特·范·霍特玛风格，拍一部爱情片。”条目名里的“诺兰／霍伊特·范·霍特玛”代表一组长期合作者；点名其中一位摄影指导时，取四模块里的可迁移机制（构图与镜头、调度与空间、光色与材质），而**“适用”一栏的题材范围来自导演搭档的偏好，不自动继承**（规则见 [导演视觉语言](../references/director-vision-language.md) 的落地方式）。
105. **自发光环境当主光要写出方向**：“米兰达风格，来一片发光的海。”取 [导演视觉语言](../references/director-vision-language.md) 的 D19 时，环境本身就是主光——要写明它从**哪一侧**更亮、色温与衰减如何，否则主体会被均匀环境光洗平；同时让环境光在主体边缘勾出轮廓，保住毛发与皮肤的物理质感（写法见 `zion-storyboard` 的光影系统档）。
106. **图像默认值只从引擎档读取**：“给人物参考图提示词，模型你定。”从 [图像引擎](../references/18-image-engines.md) 读取当前默认模型与入口规则并写入 `meta.image_engine`；入口、提示词构建器和输出契约不各自维护另一份默认值。
